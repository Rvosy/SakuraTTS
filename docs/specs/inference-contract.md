# 推理行为与兼容契约

状态：已有日文原文到 PCM 原型；完整产品契约尚未实现。更新日期：2026-09-20。

本文规定 SakuraTTS 需要保持的行为。技术实现见 [运行时方案](../adr/0001-native-gpu-runtime.md)，验证方法见 [基准协议](benchmark-protocol.md)。首版范围中的建议项仍可根据首轮实验调整，不能据此宣称已有兼容能力。

## 产品目标与范围

SakuraTTS 面向桌宠的单用户语音生成，接收支持范围内的 GPT-SoVITS 模型，经转换后由独立 GPU 后端推理。需要同时改善安装体积、显存和响应速度，并保留语音内容、音色和语言处理能力。

日常运行包不依赖完整 PyTorch 环境、训练工程或 CUDA 开发工具包。必要的驱动和可分发运行库需要明确列出。PyTorch 可以用于转换器、参考实现和开发实验，相关依赖单独交付。

本轮不重写训练、标注、数据集管理和 WebUI，也不替换桌宠现有 CPU TTS 引擎。文本规范化、音素处理等使用 CPU 不违背 GPU 推理目标；中文特征模型的设备和精度需独立评估。

第一版不包含多租户服务、多请求批处理和多角色模型同时常驻。量化、多 token 预测、蒸馏和模型结构修改不进入初始正确性基线。

## 初始兼容范围

开发验证先在 Mac 上完成“朱雀院红叶”V2Pro 对照，随后在 Windows / RTX 5060 8 GB 接通 Sakura V2ProPlus 的独立日文 WAV 路径。两组权重、前端版本和设备的证据分别保存。Windows 质量、干净机器部署、流式与宿主集成尚未完成整体验收；下表仍是产品设计范围。

| 项目 | 当前建议 | 纳入支持范围的条件 |
|---|---|---|
| GPU | NVIDIA CUDA | 确定 GPU 架构、显存、驱动和运行库版本，并在实机验证 |
| 操作系统 | Windows | 在目标系统完成构建、干净安装、冷启动和推理验收 |
| 模型 | Mac：“朱雀院红叶”V2Pro；Windows：Sakura V2ProPlus | 固定权重哈希、真实配置和官方参考身份，通过转换与中间结果对照 |
| 其他 V2 / V2Pro / V2ProPlus 权重 | 后续逐项扩展 | 分别验证说话人条件、模型结构、采样率和输出行为 |
| V1 / V3 / V4 等 | 暂不列入首版 | 单独分析计算链路，不能按 V2 权重布局解释 |
| 语言 | 近期先支持日文；中文及混合语言暂缓 | 固定文本前端和语言资源，逐项验证后公布能力 |
| 并发 | 一个活动模型组合、一个 GPU 请求，`batch=1` | 同时到达的请求得到明确的忙碌结果，不隐式共享解码缓存 |

模型兼容指支持转换与推理，不要求运行时直接读取任意 `.ckpt` / `.pth`。文件扩展名和文件名不能用于断定结构。未知版本、缺失权重、形状不符或语言资源不匹配必须给出具体诊断，不能静默套用另一模型配置。

## 模型包与参考条件

转换器读取原始权重和配置，输出独立模型包；不覆盖原始模型。第一版允许调整权重布局、部署格式、执行精度及删除无输出依赖的计算，保留原网络结构与行为。精度变化必须记录并验证。

模型包、参考条件和运行结果的 JSON 使用 UTF-8，读取与写入均明确指定编码，不依赖操作系统区域设置。来源路径和日文参考转写必须保持原字符。

Windows 配置通过 `sakuratts synthesize --config` 指定 GPT、声学、前端和参考包。包内保留的原始路径只作来源记录，日常运行不得依赖它们读取官方源码、原角色资源或开发环境。准备和转换工具拒绝覆盖不同资源，不在原目录生成缓存或自动下载缺失文件。

日文前端的实现、版本和主字典是行为契约的一部分。经典 `pyopenjtalk 0.3.4` 与 `pyopenjtalk-plus` 不默认等价；经典包显式记录 `japanese_g2p` profile，并将模块、词典和许可文件纳入包哈希。不能仅因两者都提供 G2P 接口而在对照时替换。

`doctor --nvidia --config` 仅检查环境导入、资源完整性和身份，不加载 TTS 模型或执行 CUDA 推理。诊断输出必须区分已实现后端、依赖检查、资源检查和未执行的推理、质量验收；检查通过不能表述为生成内容完整或音质合格。

模型包至少需要表达以下信息。这里规定信息内容，文件格式和字段名在首个转换器中确定。

| 信息 | 用途 |
|---|---|
| 包格式版本、模型家族、配置与原始权重哈希、转换器版本 | 定位转换来源，判断能否加载 |
| 权重及图文件清单、内容哈希、张量布局与精度 | 校验完整性，避免按名称误用资源 |
| 层数、隐藏维度、注意力头数、词表、EOS、位置编码及采样规则版本 | 按真实配置执行，禁止写死示例模型参数 |
| 文本前端、音素表、特征模型和语言资源版本 | 保持输入语义与特征对齐 |
| 参考条件依赖、音频采样率、输出格式、已验证容量范围 | 准备参考资源并解释生成结果 |
| 运行库要求、可选量化参数、来源与再分发许可 | 明确部署依赖和可用范围 |

参考音频的语义、音色条件和参考文本特征应在准备阶段生成。普通发声只加载这些产物；创建或修改参考资源时才需要相应编码模型。

缓存身份应覆盖实际依赖，包括音频内容与预处理参数、参考文本和语言、相关模型权重、文本前端及处理版本。目标文本改变时，不能仅凭参考音频相同就复用整套 Transformer 前缀 KV。只有证明某项中间结果与变化的输入无关，才允许复用。

共享语言资源按内容身份复用。不同微调权重即使文件同名，也不是同一份模型。硬件编译缓存应与模型、GPU 和运行库条件绑定，可重建、有容量限制，并与用户原始模型分开管理。

## 模型计算不变量

### 文本与特征

日文首阶段只接受已经验证的语言模式及参考条件；识别到不支持的语言段时明确拒绝，不能删除、强制改读或伪装成日文。该路径遵循官方日文零 BERT 特征语义，无需加载中文特征模型。中文恢复后仍保持下述完整 BERT 约束。

分句、规范化、音素序列、音素与文本特征对齐方式需要与固定版本的参考实现对应。中文 BERT 特征不能在兼容模式下静默关闭。

若裁剪文本特征图，只能删除目标输出不依赖的计算；必须验证取的是同一中间层、相同特殊 token 处理和相同音素映射。不能把“移动到 CPU”“降低精度”和“取消特征”当作同一种优化。

### 注意力与 KV

对首批 V2 模型，需要保留以下注意力关系，并以实际参考实现的掩码测试验证：

- 文本部分内部双向可见，文本不能读取音频 token。
- 音频部分可以读取有效文本，并按因果顺序读取音频历史。
- Padding 和未使用的缓存槽位不能参与注意力归一化；填零不能替代掩码。

Prefill 指首次处理文本和参考语义前缀，Decode 指后续单 token 生成。两者可以使用不同执行方式，但位置编号、缓存有效长度和输出必须衔接一致。

首版使用连续、预分配的 KV；精度随经过验证的执行模式确定，当前 Mac 基线为 FP32，FP16 待独立验收。容量包含文本、参考语义和生成部分，按真实 token 数安排。写入新 K/V 不应重新拼接整段旧缓存；运行时需要验证这一点，不能只根据 `scatter`、静态 shape 或 I/O Binding 的名称判断。

达到容量或生成上限时应报告具体停止原因。长度预测只能用于容量与调度，不能替代 EOS，也不能把截断作为正常完成。

### 解码与精度

Embedding、位置编码、残差、LayerNorm、激活函数及执行顺序遵循对应模型。融合不能把 LayerNorm / ReLU 等替换为其他架构的算子语义。

采样需保留参考版本的温度、重复惩罚、Top-k / Top-p、首步限制和停止规则，包括规则的应用顺序。默认值变化须作为行为变化记录，不能用于制造速度优势。

当前 Mac 高精度基线继续保留；FP16 是待验证的产品候选，不能在数值、语音质量与目标硬件验证前替代它。归一化、概率计算或累加可保留必要的较高精度。量化另设可选配置，记录模块、位宽、分组、校准来源和质量结果。

当前 Mac GPT 原型的 Prefill 精度由调用方显式选择。`MLXGPT.load(..., prefill_precision="fp32")` 保留原默认路径；`"fp64"` 使用同一 FP32 权重包，在 CPU 上逐层临时转为 FP64 计算，完成的 K/V 与首步 logits 一次舍入为 FP32，再接续原 FP32 Decode。不常驻完整 FP64 权重副本，也不修改模型包。`prefill(..., precision=...)` 只覆盖本次调用，不改变加载时的选择。

精度选择不能依据特定句子、位置或已有失败样例自动改变。每种模式独立记录数值验收、CPU/GPU 工作分配、正常请求时间和资源成本；原 FP32 路径的已知失败继续保留。高精度 Prefill 通过固定历史检查，不等于完整生成、采样或语音质量已经通过。

不同后端的浮点顺序和随机数实现可能不同。同种子音频逐样本一致不是唯一标准：先对照固定历史下的中间张量和 logits，再验证采样分布和端到端语音。

## 请求、流式输出与取消

宿主提交文本、语言、已准备的角色资源和生成参数，接收有序 PCM 块及请求结果。具体 C ABI、进程通信方式和函数名尚未确定；以下是接口必须表达的语义。

每个音频块归属一个请求，并包含顺序、采样率、通道数和样本格式。单次请求内格式稳定；声学上下文重叠只用于计算与拼接，不能重复播放。请求最终进入完成、取消或失败中的一个终态，携带正常 EOS、长度限制等可区分的原因。

首块必须在完整语音生成结束前可供宿主消费，才称为流式输出。仅将已完成的音频切片不算降低首包延迟。

音频队列和工作区有界，宿主消费过慢时施加背压，不能无限积压。小首块、后续较大块是候选策略，具体块长、重叠和前瞻由声学依赖及测试决定。

取消在明确的调度边界生效；确认取消后不再发布该请求的新音频。GPU 在途工作结束前不能释放或复用它引用的内存。取消延迟需要测量，不能承诺立即中断一个正在运行的 kernel。宿主负责丢弃尚未播放的旧请求音频，已播放的音频不在引擎回收范围内。

当前片段遇到 EOS 后，后续预提交步骤不能继续写入该片有效 token 或发布多余音频。多片段请求仍须处理后续文本；长度限制同样只终止当前片，完整请求另行汇总是否存在受限片段。失败需要保留阶段、原因和必要上下文，不能伪装为正常空音频，也不能静默切换到 CPU 产品路径。

## 资源生命周期

运行时统一拥有模型、缓存和执行状态。首版按需准备一个活动模型组合，避免为全部角色、batch 和容量档位提前分配。

| 资源 | 生命周期 |
|---|---|
| 模型权重 | 模型加载至卸载；Prefill 与 Decode 应避免重复驻留相同权重 |
| 参考特征编码模型 | 参考准备期间；结果保存后可释放 |
| 参考条件 | 与对应资源版本绑定，可跨请求复用 |
| KV、token 历史、当前位置、停止标志 | 当前片段；每片以同一参考和本片目标重新 Prefill，完成、失败或取消后重置 |
| CUDA Graph 与绑定地址 | 关联模型和缓冲区有效期间；地址变化后失效并重建 |
| Prefill 临时空间、Decode 临时空间、声学生成工作区 | 无重叠执行依赖时复用，异步工作完成前不回收 |
| PCM 输出缓冲区 | 宿主消费或取消丢弃后复用 |

角色切换须先处理旧请求，旧请求结果不能进入新角色的输出。相同模型可以复用权重，参考条件与请求状态仍需正确切换。

`MLXSoVITS.load(..., reference=prepared_reference)` 可显式绑定一个日文参考：先按原 FP32 运算准备五项声学投影，再加载不含这 14 个条件权重的模型实例。绑定保存独立的参考身份和 `ge/ge512` 快照，不能通过修改调用方对象更换参考；错配须在声学 RNG 消耗前拒绝，直接 `decode` 也要核对条件。更换参考需要新建实例，不提供原地重绑。省略 `reference` 继续加载完整权重，模型包保持完整；WeightNorm 折叠与 softmax 精度仍是独立选项。

当前非流式 Python 原型可分两阶段调用：`generate_prepared_semantic` 返回绑定目标音素、参考条件和随机数状态的 CPU 数据，随后由 `synthesize_acoustic` 生成音频。阶段结果不持有 GPT 模型、KV 或调用回调，调用方可在两个阶段之间卸载 GPT，再加载 SoVITS。声学阶段不能另传一组参考条件；模型身份和参考身份在使用前验证。已有 `synthesize_prepared` 组合入口继续可用。

分阶段执行保持同一个 RNG 的消耗顺序，不能在声学阶段按 seed 重新初始化。调用方不能在阶段之间修改绑定输入或推进共享 RNG；显式回放 draw / noise 不消耗对应随机数。阶段计算时间不含中间加载、卸载或等待，完整请求耗时由调用方另测。

非流式日文 CLI 用 `prepare_text_request` 一次准备原文的全部 `cut0` 片段，再按官方顺序逐片完成语义和声学生成。整条请求仅初始化一次 RNG，消耗顺序为 GPT 采样、该片声学噪声、下一片 GPT 采样。每片独立归一化并追加尾部静音，最后顺序拼成完整 PCM；全部成功后才写 WAV。旧 `prepare_text` / `synthesize_prepared` 单片接口保持原有范围，遇到多片明确拒绝。

实验性的 `split_method="cut2"` 必须显式选择并记录；默认 `cut0` 不自动回退或切换。它只采用固定官方分句规则，不改写原文。不同分句方法会改变目标条件、片数和随机数消耗，对照须使用同一方法，不能要求不同方法波形相同，也不能将较短分片的成功视为原方法的内容问题已解决。

换行不保证产生独立片段，短片合并与 510 字符分割仍遵循官方规则；字符分割不保证 GPT KV 或位置容量足够。CLI 逐片记录停止原因、PCM 偏移和长度；任何片达到次数限制，处理完后续片后退出 `2`，不将受限音频标为完整内容验收。后片推理失败时，不写出前片组成的不完整 WAV。

公开 Python 生成接口另接受 `cancel_requested` 谓词。它在 Prefill 前后、每步采样后、Decode 返回后、声学执行前后检查取消，抛出带 `stage` 的 `SynthesisCancelled`，不返回部分音频。阶段结果不保留谓词，分阶段调用者须向两次调用显式传入同一取消来源。检查点只在已完成的计算边界生效，不中断在途 kernel；`release_gpt_state=True` 的语义阶段 `finally` 也覆盖取消。模型卸载仍由调用方负责。

卸载后应释放模型、图和工作区持有的资源，报告进程实际剩余占用。驱动上下文仍可能有基础开销，不能据此承诺显存归零。空闲保留模型与卸载模型的下一句延迟分别测试。

## 完成条件

兼容范围内的模型能完成转换、加载、生成和取消；正确性、质量、资源与部署检查均按 [基准协议](benchmark-protocol.md) 提供证据。没有实测的模型、语言和硬件继续标为未验证。

当前 Windows 实机为 RTX 5060 8 GB，官方基线与自有运行时测量单列在 [Windows 实测记录](../experiments/2026-09-20-windows-nvidia-backend.md)。尚无用户批准的具体 MiB / ms 预算；默认策略优先保留实测不退步或波动范围内的速度，明显变慢的省显存策略单列。性能测量、数值容差和质量检查均保留原始结果，不能因环境或单次生成成功宣布整体目标达成。
