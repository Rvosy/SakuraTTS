# 效果演示素材

## 录制

打开平时使用的桌宠，选好 SakuraTTS 音色。要演示提前唤醒，开启空闲休眠，等引擎进入休眠再发送消息。

打开[全屏录制底色](recording-background.html)，按 F11，再把置顶的桌宠放到前面。底色与演示画布同为 `#FAF9F5`（RGB 250、249、245）。也可以用[同色 4K PNG](recording-background.png)铺满录制区域。让输入栏保持平时的透明度，边缘、阴影和毛玻璃效果都会与这层底色一起录下。

在 OBS 中用显示器采集，同时收录桌宠语音。裁切范围要容得下角色、展开后的对话框和整条输入栏，预览一次最长的气泡。先开始录制，再点进输入栏，输入文字、发送，等角色说完，并录到引擎再次休眠。

## 素材与对时

保存原速、连续的 MP4 或 WebM。同底色 MP4 可以直接回放，带 Alpha 通道的 WebM 也可直接叠在画布上。取同一段时间的引擎诊断文件 `logs/sakuratts.log`，以及桌宠用户数据目录 `data/logs/` 下的 `sakura-runtime.log` 和 `sakura-plugins.log`。独立启动引擎时，控制台的「日志」一行给出诊断文件的实际路径。桌宠菜单里的「运行日志」可以找到宿主与插件记录。

记下视频第一帧对应的本地时间。也可以用画面中的发送动作与同次请求日志对齐，用日志时间减去动作在视频中的秒数，得到近似起点。桌宠文本日志只精确到秒，服务诊断日志带毫秒；细调时对照录音里第一声和桌宠动作。宿主和插件文件只保留本次录制的节选，因为这两类文本行只含时分秒。

## 回放

把素材放到本页旁的 `take` 目录，在 `docs/showcase` 中运行下面的命令。将示例时间和时长换成这次录制的实际值，可省略没有采集的日志文件。

```powershell
python prepare_replay.py --start "2026-11-24T14:30:05.250" --seconds 24.8 --video take/pet.mp4 take/sakuratts.log take/sakura-runtime.log take/sakura-plugins.log
```

脚本更新 `replay-data.js`。重新打开「效果演示」并点击「播放回放」。终端默认按时间显示引擎的 INFO 及以上级别输出，以及宿主的时序事件。点击「原始日志」可查看同一时刻的完整原文，包括 DEBUG、路径和 HTTP 轮询。长行可以横向滚动。

回放以视频为时钟。对话时序中的等待、加载、合成和播放共用一条时间轴。最后一次播放结束后，如果只剩引擎等待休眠，图表切换到这段时间的服务状态。需要剪掉等待时，先录下完整演示页，再剪合成后的画面和声音。

随页预览从 2026-11-13 22:40:13 开始，共 78 秒。22:40:17，桌宠在同一秒记录了等待模型回复和提前加载请求。运行状态在 22:40:18 观测到加载，22:40:23 观测到模型就绪，22:40:25 收到回复。播放于 22:40:38 结束，22:41:27 观测到再次休眠。桌宠日志精确到秒，引擎日志带毫秒。首次打开从唤醒前开始回放。右侧以 Sakura 的 `characters/Sakura/portraits/A020.png` 和对话、输入区域示意构图，正式回放时由桌宠录屏替换。
