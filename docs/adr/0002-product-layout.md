# ADR 0002：公共 Engine 与研究材料分离

状态：已接受。日期：2026-09-20。

平铺的运行时模块、专项 Harness 和逐次实验报告让首次使用者难以找到入口。已有推理行为和独立 Python ABI 工作进程包含大量验证，目录整理不同时重写计算实现。

低级 Python API 收敛到 Engine、Model 和 Audio。CLI 和 HTTP 调用同一 Engine；model.json 引用原有资源包。CUDA / ONNX / MLX 按后端组织，前端与第三方派生实现单独归类，私有 worker 继续只加载目标 SakuraTTS 包。

HTTP 沿用 GPT-SoVITS api_v2 的字段和默认值，在单一线程中创建、调用、切换和关闭引擎，忙碌请求返回 409。服务和转换依赖是可选 extras。当前只将已有 Windows CUDA 日文链路接入公共 Engine，没有为尚未交付的后端加入注册层。

历史工具和数据归档到 research/，常用基准从 benchmarks/ 进入。此次保留已引用证据，避免文档中的失败和性能结论失去来源；新的输出不入 Git。

模型与参考在服务接口上分开：启动只加载明确配置的模型，参考由原版请求指定。已有参考包只作为缓存；新音频通过独立准备进程编码。选择这一边界是为了减少调用方迁移成本，并让主推理环境继续不依赖 PyTorch。准备新参考和转换原始权重仍需配置相应环境。

代价是内部导入路径变化，外部研究脚本需要迁移。旧文档公开过的 NVIDIAEngine 和 synthesize CLI 保留兼容入口。文件没有机械合并成大型后端模块，第三方许可及独立进程边界仍保持可审查。
