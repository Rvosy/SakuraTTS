# ADR 0001：分离模型转换与轻量 GPU 运行时

状态：已采用。初始日期：2026-09-19。Windows 路径于 2026-09-20 接通。后端和发行组合的后续边界见 [ADR 0004](0004-composable-components.md)。

## 原因

SakuraTTS 保留 GPT-SoVITS 的模型与参考条件语义，同时减少普通推理所需的依赖、常驻辅助模型和资源复制。模型转换、参考编码与生成语音有不同的依赖和生命周期，分开交付可以让主推理环境独立于 PyTorch。

## 决定

原始检查点由独立工具转换为推理模型包。参考准备保存可复用的语义与音色条件。主运行时负责文本前端、模型加载、生成、采样、取消和音频输出。

Windows 路径采用 CuPy CUDA GPT 与 ORT CUDA 声学执行。GPT 复用模型权重和预分配 KV；声学使用转换后的计算图。PyTorch 留在转换、参考准备和开发对照环境。

声学运行库与主环境使用不同的 Python ABI，因此采用独立持久工作进程。经典日文前端也在私有解释器中执行，以保留固定版本的 G2P 与词典行为。工作进程只加载指定的 SakuraTTS 代码和自身依赖。

计算库承担矩阵乘法、卷积等通用运算；专用内核依据实际性能分析引入。文本规则、模型行为、随机数消耗和资源所有权按[推理契约](../specs/inference-contract.md)验证。

## 代价

项目需要维护转换器、权重映射和运行库分发。独立进程增加启动、通信和主存成本；卸载资源则增加下一句加载时间。这些成本计入完整请求与部署测量，性能和质量证据见[兼容矩阵](../specs/compatibility-matrix.md)。

MLX 保留为研究实现。C++、TensorRT、量化等初始候选尚未成为公共运行后端；初始讨论、未采用方案及复审条件保存在[原始方案记录](https://github.com/Rvosy/SakuraTTS/blob/main/research/notes/native-gpu-runtime-proposal-20260919.md)。
