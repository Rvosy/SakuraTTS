### 日文主线的验收顺序

| 阶段 | 实现内容 | 进入下一阶段的证据 |
|---|---|---|
| 日文完整请求 | 原始文本、实际语言识别、音素和韵律、参考条件包、自有生成与 PCM | 四条已有日文长短句 / 多句 / 标点回归及原失败句；固定条件的中间结果与音频，单独记录试听 |
| 参考与请求生命周期 | 新日文参考由独立准备工具生成；日常运行不加载辅助编码模型；请求重置、失败、卸载和参考更换边界 | 新参考可重载、同请求可复现，前后请求无状态污染；加载 / 空闲 / 生成 / 卸载资源记录 |
| 统一验收与分发边界 | 日文依赖清单与干净环境入口；冷启动、首次与多次热运行，同一报告保留所有阶段成本 | 不依赖中文模型或完整 Torch；计时区分诊断与正常运行，非流式完整完成时间不标为流式首包 |
| Windows 接续包 | 真实 shape、模型身份、参考条件、固定随机输入和阶段输出；明确 GPU 状态 / 采样 / KV 更新边界 | 能重放正确性与已知失败；剩余热点确实依赖 CUDA profiler、内核、精度或真实显存 |

独立随机生成需要多 seed 的内容、停止、音色和自然度检查，不能只凭固定噪声 token 相同通过。流式先研究完整句子或合理分句；声学非因果注意力的任意切块不能靠重叠就宣称等价。参考语义与音色条件可以缓存，GPT 参考前缀 KV 受当前目标文本影响，不跨文本直接复用。

中文代码、原始失败样例与证据不删除，通用改动可以复跑既有回归。暂缓的是新增中文整链、资源和数值专项；恢复后仍要求完整 BERT 与官方规则，不用省略功能换取内存数字。


## M0：固定范围并建立基线

首个对照样本已固定为“朱雀院红叶”V2Pro，并记录上游提交、权重哈希、参考音频、中日文文本及采样参数。生产系统已定为 Windows / CUDA，接下来固定 GPU 和代表性测试集，继续清点必需模型、语言资源和部署依赖；原有整合包的完整体积基线尚未取得。

按基准协议比较官方普通路径、官方可用的 CUDA Graph 路径、Lite 非 Flash / Flash 路径。中文特征完整启用时的结果单列，参考准备与缓存命中分开。无法运行的路径保留原因。

交付物：可复现环境与输入清单、原始时间和内存记录、输出音频、磁盘分类清单、已填写的性能预算与质量标准。

完成条件：知道主要体积、显存和延迟来自哪里；基线能力相同；后续验收有事先固定的对照和阈值。只有下载模型或跑通一句话不算完成。

## M1：转换模型与建立正确性对照

对首个模型实现可复现的转换，保留真实配置和权重来源。确定推理包的最小格式，拆开参考条件准备与日常发声资源；检查文本前端和特征模型所需计算及依赖。

导出固定文本特征、参考条件、Prefill、单步 Decode 和声学生成的对照数据。确定数值容差，特别验证混合注意力掩码、位置、KV 边界和采样顺序。

交付物：一个可校验的推理模型包、参考条件产物、转换记录和中间结果对照入口。

完成条件：转换不修改原始模型，独立加载端能读取模型包；中间结果通过约定检查；未知结构得到明确诊断。此时不要求已经实现完整原生语音生成。

## M2：独立端到端推理与后端定案

先在现有 Mac 上接通已验证的自有模块，优先完成可迁移的包格式、文本与参考准备、加载和生命周期。保留高精度对照，测量权重驻留、KV 更新、动态长度、工作区和冷启动。CUDA 候选及 FP16 计算待实机条件满足后独立验证，不预先固定生产后端。

完成模型包、文本前端、参考条件、语义生成、声学 / 波形生成到 PCM 的最小原生链路。先单请求完整生成，再进入流式优化。

交付物：可运行的独立原型、依赖清单、正确性及干净环境运行记录、后端选择结果。

完成条件：不依赖 PyTorch 训练环境也能完成端到端生成；中间结果和语音质量达标；已测量总资源与冷启动成本。根据证据更新 ADR，确定一条生产主路径。

如果所有候选都达不到要求，记录失败环节并收窄实验，不能以增加更多生产后端代替选择。

## M3：执行优化、流式输出和生命周期

用正常运行数据和 profiler 定位瓶颈，逐项加入完整单步执行图、GPU 采样与状态更新、必要算子融合、按依赖复用中间特征，以及声学工作区限制。

实现有界流式音频、背压、取消和角色切换。先确认所需上下文，再确定首块、后续块、重叠与前瞻；不默认反复转换全部历史，也不任意删掉非因果依赖。

交付物：单项优化前后结果、流式质量对照、取消 / 切换 / 卸载的行为与资源记录、端到端性能报告。

完成条件：满足已固定的体积、显存、延迟和质量预算；多轮运行无持续资源增长；EOS、容量限制及取消不会产生旧请求音频。只有 token/s 上升不能作为完成依据。

## M4：分发与 Sakura 集成

整理运行包、共享语言资源、角色模型、参考准备工具和转换器的发行边界，记录每项再分发要求。实现可重建且有限额的硬件缓存，计入首次运行后的磁盘占用。

核对 Sakura 当前 TTS Provider / Runtime Pack 接口，连接请求、PCM、取消和错误传递。保留现有 CPU 方案的产品边界。

交付物：目标系统的安装包与依赖说明、干净安装记录、真实桌宠的播放 / 取消 / 角色切换验证、与其他 GPU 负载共存的测量。

完成条件：用户不安装完整训练环境或 CUDA 开发工具包即可使用支持范围内的模型；安装及首次运行体积符合预算；实际宿主集成通过。此阶段通过才算首版交付完成。

## M5：可选量化与模型扩展

在 FP16 基线保留可用的前提下，分别尝试 GPT 线性层 W8 / W4A16、文本特征量化和 SoVITS 局部量化。KV 先评估 INT8 的净收益，再决定是否研究更低位宽。

每项实验记录质量、磁盘、显存和延迟。只压缩文件却增加运行成本的模式不默认启用。首个 V2Pro 样本之外的权重及 V2ProPlus 等模型结构按实际样本逐项扩展兼容矩阵。

投机解码、额外预测头、TurboQuant 等保留为后续研究线索，先补齐原始论文、模型条件和训练要求，再决定是否立项。这些不阻塞首版 FP16 产品交付。

## 首轮实验顺序

| 实验 | 要回答的问题 | 决策依据 |
|---|---|---|
| 整合包与运行依赖清点 | 超过 8 GB 的占用由什么构成 | 实际文件清单、共享资源与首次运行缓存 |
| 参考准备拆分、模型去重 | 移除不必要常驻资源能省多少 | 加载 / 首句 / 热推理峰值与质量一致性 |
| 文本特征图裁剪与设备选择 | 无用计算裁剪和 CPU / GPU 放置的净影响 | 相同中间特征、完整 TTFA、CPU 与显存占用 |
| 连续 KV 和 Decode 子图 | 是否消除了整段复制、重复分配与同步 | 固定历史的 logits、设备轨迹和分配记录 |
| SoVITS 子图与片段长度 | 声学工作区是否成为主要成本 | 质量、TTFA、RTF、上下文长度及峰值 |
| 最小运行包启动 | 原生路径是否真正减轻分发 | 完整依赖、JIT、安装后及首跑后体积 |

不先搭建完整多后端抽象，不先实现一组未经定位的 CUDA 内核。实验代码在证明收益之前不自动成为产品依赖。
