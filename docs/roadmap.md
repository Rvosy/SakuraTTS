# 产品路线

项目以完全兼容 GPT-SoVITS 为目标，在保持模型行为和调用语义的基础上优化推理速度与资源占用，覆盖 CPU、NVIDIA CUDA、AMD GPU 与 Apple M 系列。目录和函数职责以固定上游版本为主要参照，各设备实现按硬件特点优化。完整兼容目标、当前缺口和实测结果由[兼容矩阵](specs/compatibility-matrix.md)维护。

## 工作顺序

- 优先缩短完整请求耗时，同时测量首次执行、热请求、生成 token 数、音频长度、峰值和空闲资源占用。CPU 继续优化 INT8 GPT 与 FP32 声学；AMD 优化 FP16 GPU GPT、KV 驻留与声学执行；NVIDIA 延续 FP16 与 CUDA Graph；Apple 在现有 V2Pro／FP32 流程上扩大设备、系统和模型验证范围。
- 为四类设备提供可选择的执行档位。FP16、INT8 等候选分别检查数值、生成行为与听感；不把缩小权重文件等同于实际提速。内存优先模式明确记录额外加载耗时，速度优先模式记录常驻资源。
- 按兼容矩阵补齐模型家族、语言、配置、API V2、旧版 API、原版 Python 调用及 Gradio 集成。逐项对照输入、默认值、错误和输出行为；训练与数据工具的产物及联动流程也需要独立核对。未实现项继续明确报错，不因已有推理子集可用而从目标中排除。API V2 的字段支持状态见 [API V2 使用说明](api-v2-guide.md)。
- 英文与日英混合已接入，继续验证更多权重、参考转写和听感；随后接通中文 G2PW、BERT 与自动语言路由。每种语言同时验证目标文本、参考文本、连续切换和失败恢复。
- 扩大后台控制模式验证：测量不同提前量、H 档反复睡醒与数小时待机，再依据结果决定是否增加执行预热、CPU 权重缓存或调整保活默认值。
- 在第二台干净 Windows 机器验收完整整合包，覆盖原始权重转换、新参考、缓存复用、搬迁与首次请求，明确驱动和硬件范围。
- 完成各档位的长句内容、音色和自然度验收，保留 FP16 相对 FP32 的数值失败记录。实际宿主另验播放、取消、切换与长期资源释放。
- 精简准备组件中由上游导入带来的额外依赖，补齐公共辅助权重与二进制的分发材料。

## 扩展设备

CPU 与 Windows DirectML 已接入公共 Runtime，详见 [CPU / AMD 指南](cpu-amd.md)。继续优化 CPU GPT、AMD 核显的延迟与共享内存，补齐长句听感、更多硬件和整合包验收。Apple 的 MLX 原生 V2Pro 路径与 Windows V2ProPlus 转换链分开验证，转换、新参考与整合包已接入，继续验收旧系统、其他 Apple 芯片与长文本音质。

新增后端或语言时，先完成模型导入、新参考、目标文本、流式、取消、切换和睡醒，再纳入发行 recipe。各组合按实际依赖交付并独立测量体积。Windows 日文完整包的压缩目标为 2 GB，其他组合另设预算。

早期里程碑与当时进度保存在[2026-09-20 路线记录](https://github.com/Rvosy/SakuraTTS/blob/main/research/notes/roadmap-20260920.md)。
