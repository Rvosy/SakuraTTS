# 实施路线

状态：已完成 Mac 上游功能验证，已有自有 GPT、中文 BERT 和完整声学计算原型；文本与参考准备尚未接通，完整语音运行时仍在研发。更新日期：2026-09-19。

目标与行为约束见 [推理契约](specs/inference-contract.md)，架构选择见 [ADR 0001](adr/0001-native-gpu-runtime.md)，测量规则见 [基准协议](specs/benchmark-protocol.md)。各阶段按证据推进，不按预估加速倍数或日历日期宣布完成。

## 当前状态

- 已完成聊天记录整理、三个主仓库的定点源码核对和部分论文题录 / 摘要核对。
- 已形成范围、架构提案、研究记录和验收协议。
- 已在独立目录固定三个上游仓库、两个 Python 环境和模型来源，新增参考 Harness。
- 使用用户选定的“朱雀院红叶”V2Pro，在 Apple M4 的 MPS / FP32 路径完成官方与 Lite 的中、日文合成，保存 8 个 WAV 及原始结果。详见 [Mac 首轮验证](experiments/2026-09-19-macos-reference-smoke.md)。
- 已建立 10 条回归语料，追踪官方与 Lite 前端、参考、采样与切片差异；相同官方历史下，日文 121 步、中文 147 步 GPT logits 完全一致。参考辅助模型释放实验保持既有 WAV 哈希。见 [调用链与资源实验](experiments/2026-09-19-parity-and-lifecycle.md)。
- 用户已确认指定官方与 official_text 候选的开头和助词正常；后续两条原始回归的自有整链样音也获确认“四条都正常，未听出明显差异”，覆盖全文和音色。其余八例仍无人工验收。Windows 验证暂缓，产品目标 NVIDIA GPU、首发系统及性能预算尚未固定。
- 参考资源释放与 BERT 无依赖层裁剪已通过 10 条中日文及混合输入的逐文件波形回归，请求结束 allocated 边界少约 698 MiB；独立内存采样仍显示较高瞬态 driver 占用。见 [资源实验](experiments/2026-09-19-bert-and-reference-memory.md)。
- 已实现 GPT FP32 模型包转换和独立 MLX / Metal Prefill、Decode，固定两条历史的全部 logits 在预设容差内，运行环境未安装 PyTorch。见 [MLX 实验](experiments/2026-09-19-mlx-gpt.md)。
- 扩展固定历史暴露日文长句第 329 步 MLX 数值超差，未放宽容差；CPU FP64 Prefill + MLX FP32 Decode 的 10 条、1805 步 logits 全部通过。正常测量中 8 条更快、两条短句更慢，详见 [数值与成本](experiments/2026-09-19-mlx-numerics.md)。[十例自有历史生成](experiments/2026-09-19-expanded-native-generation.md)的 token、停止和切片相同，但两例三个采样概率值超差，整体仍按失败记录。
- 独立 MLX 中文 BERT 的 CPU 路径通过 5 段逐层对照，空闲 RSS 少约 109 MiB；短句慢约 2%–7%，GPU 仍有一个中间元素超差。见 [BERT 实验](experiments/2026-09-19-mlx-bert.md)。
- 自有 MLX 码本、声学编码器、reverse flow 和声码器已接通。CPU encoder + GPU flow/decoder 下，十例最终波形通过；日文标点的一个 MRTE 中间元素超差。已将首层差异追到 [softmax 舍入](experiments/2026-09-19-attention-softmax-numerics.md)；统一 FP64 LayerNorm 因长句波形退化被否决。此前正常声学生成比官方慢约 29%–41%，后续调度结果单独记录，不混用实验条件。
- 单参考声学条件预计算保持 10 条 WAV，请求后 allocated 再减少 148.99 MiB；独立采样复测的生命周期 RSS 峰值基本不变，原先的大幅上升未重现。请求区间观察到的 allocated 最大值少约 143 MiB，driver 下降有限。见 [声学生命周期](experiments/2026-09-19-acoustic-lifecycle.md)。
- 三个权重包采用逐张量无损存储后，归档少 801.37 MiB，运行时恢复原 FP32 权重。[复用已加载权重](experiments/2026-09-19-gpt-prefill-weight-reuse.md)去掉高精度 Prefill 重复读取与校验，在相同紧凑包的两条请求中快约 17%；十条固定历史 logits 逐位保持。不把磁盘收益算成运行内存收益。
- 中文 tokenizer 已移除 Transformers；[G2PW 输入](experiments/2026-09-19-g2pw-inputs.md)、[文本准备](experiments/2026-09-19-g2pw-text.md)和 [CPU ONNX Session](experiments/2026-09-19-g2pw-onnx.md)分别通过官方对照，正在接通完整拼音输出。三轮创建、关闭后的 RSS 在约 380 MiB 趋稳，尚不能据此判断长期泄漏。完整前端仍需中文变调、日文 prosody 和混合语言处理。
- 准备好官方文本和参考条件后的自有 GPT → 声学 → PCM 已扩展到十例，token、停止和最终波形对照通过；仍保留独立概率和 MRTE 超差。见 [十例整链](experiments/2026-09-19-expanded-prepared-speech.md)。该路径不包含原始文本和参考准备，也不等于独立 RNG 验收。
- [声码器逐残差对求值](experiments/2026-09-19-decoder-workspace.md)保持十例波形逐位不变，两条短句的 decoder 分配器峰值约降 45%，decoder 耗时增加约 10%–14%。结合可选 GPT 按请求释放，两条准备条件的短请求测到 622.05 MiB MLX 高水位；十例常驻策略轮则为 1,989.12 MiB。这些数据含义和条件不同，不代表完整 TTS 或统一的模型显存指标。
- 自有轻量运行时仍在研发，没有原始文本到音频、正式音质、流式或干净部署验收结果。

## M0：固定范围并建立基线

首个对照样本已固定为“朱雀院红叶”V2Pro，并记录上游提交、权重哈希、参考音频、中日文文本及采样参数。接下来固定产品目标 GPU / 系统和代表性测试集，继续清点必需模型、语言资源和部署依赖；原有整合包的完整体积基线尚未取得。

按基准协议比较官方普通路径、官方可用的 CUDA Graph 路径、Lite 非 Flash / Flash 路径。中文特征完整启用时的结果单列，参考准备与缓存命中分开。无法运行的路径保留原因。

交付物：可复现环境与输入清单、原始时间和内存记录、输出音频、磁盘分类清单、已填写的性能预算与质量标准。

完成条件：知道主要体积、显存和延迟来自哪里；基线能力相同；后续验收有事先固定的对照和阈值。只有下载模型或跑通一句话不算完成。

## M1：转换模型与建立正确性对照

对首个模型实现可复现的转换，保留真实配置和权重来源。确定推理包的最小格式，拆开参考条件准备与日常发声资源；检查文本前端和特征模型所需计算及依赖。

导出固定文本特征、参考条件、Prefill、单步 Decode 和声学生成的对照数据。确定数值容差，特别验证混合注意力掩码、位置、KV 边界和采样顺序。

交付物：一个可校验的推理模型包、参考条件产物、转换记录和中间结果对照入口。

完成条件：转换不修改原始模型，独立加载端能读取模型包；中间结果通过约定检查；未知结构得到明确诊断。此时不要求已经实现完整原生语音生成。

## M2：独立端到端推理与后端定案

先在现有 Mac 上接通已验证的自有模块，保留高精度对照，测量权重驻留、KV 更新、动态长度、工作区和冷启动。CUDA 候选及 FP16 计算待实机条件满足后独立验证，不预先固定生产后端。

完成模型包、文本前端、参考条件、语义生成、声学 / 波形生成到 PCM 的最小原生链路。先单请求完整生成，再进入流式优化。

交付物：可运行的独立原型、依赖清单、正确性及干净环境运行记录、后端选择结果。

完成条件：不依赖 PyTorch 训练环境也能完成端到端生成；中间结果和语音质量达标；已测量总资源与冷启动成本。根据证据更新 ADR，确定一条生产主路径。

如果所有候选都达不到要求，记录失败环节并收窄实验，不能以增加更多生产后端代替选择。

## M3：执行优化、流式输出和生命周期

用正常运行数据和 profiler 定位瓶颈，逐项加入完整单步执行图、GPU 采样与状态更新、必要算子融合、按依赖复用中间特征，以及声学工作区限制。

实现有界流式音频、背压、取消和角色切换。先确认所需上下文，再确定首块、后续块、重叠与前瞻；不默认反复转换全部历史，也不任意删掉非因果依赖。

交付物：单项优化前后结果、流式质量对照、取消 / 切换 / 卸载的行为与资源记录、端到端性能报告。

完成条件：满足已固定的体积、显存、延迟和质量预算；多轮运行无持续资源增长；EOS、容量限制及取消不会产生旧请求音频。只有 token/s 上升不能作为完成依据。

## M4：分发与 Sakura 集成

整理运行包、共享语言资源、角色模型、参考准备工具和转换器的发行边界，记录每项再分发要求。实现可重建且有限额的硬件缓存，计入首次运行后的磁盘占用。

核对 Sakura 当前 TTS Provider / Runtime Pack 接口，连接请求、PCM、取消和错误传递。保留现有 CPU 方案的产品边界。

交付物：目标系统的安装包与依赖说明、干净安装记录、真实桌宠的播放 / 取消 / 角色切换验证、与其他 GPU 负载共存的测量。

完成条件：用户不安装完整训练环境或 CUDA 开发工具包即可使用支持范围内的模型；安装及首次运行体积符合预算；实际宿主集成通过。此阶段通过才算首版交付完成。

## M5：可选量化与模型扩展

在 FP16 基线保留可用的前提下，分别尝试 GPT 线性层 W8 / W4A16、文本特征量化和 SoVITS 局部量化。KV 先评估 INT8 的净收益，再决定是否研究更低位宽。

每项实验记录质量、磁盘、显存和延迟。只压缩文件却增加运行成本的模式不默认启用。首个 V2Pro 样本之外的权重及 V2ProPlus 等模型结构按实际样本逐项扩展兼容矩阵。

投机解码、额外预测头、TurboQuant 等保留为后续研究线索，先补齐原始论文、模型条件和训练要求，再决定是否立项。这些不阻塞首版 FP16 产品交付。

## 首轮实验顺序

| 实验 | 要回答的问题 | 决策依据 |
|---|---|---|
| 整合包与运行依赖清点 | 超过 8 GB 的占用由什么构成 | 实际文件清单、共享资源与首次运行缓存 |
| 参考准备拆分、模型去重 | 移除不必要常驻资源能省多少 | 加载 / 首句 / 热推理峰值与质量一致性 |
| 文本特征图裁剪与设备选择 | 无用计算裁剪和 CPU / GPU 放置的净影响 | 相同中间特征、完整 TTFA、CPU 与显存占用 |
| 连续 KV 和 Decode 子图 | 是否消除了整段复制、重复分配与同步 | 固定历史的 logits、设备轨迹和分配记录 |
| SoVITS 子图与片段长度 | 声学工作区是否成为主要成本 | 质量、TTFA、RTF、上下文长度及峰值 |
| 最小运行包启动 | 原生路径是否真正减轻分发 | 完整依赖、JIT、安装后及首跑后体积 |

不先搭建完整多后端抽象，不先实现一组未经定位的 CUDA 内核。实验代码在证明收益之前不自动成为产品依赖。
