# 产品路线

SakuraTTS 提供可嵌入的 Python 引擎、命令行和 HTTP 推理服务。当前公共入口支持 Windows / NVIDIA、已验证的 V2ProPlus 日文链路和按句流式返回。支持范围以[兼容矩阵](specs/compatibility-matrix.md)为准。

外部协议只兼容 GPT-SoVITS API v2。使用者按 [API v2 使用指南](api-v2-guide.md)中的状态表接入；尚未实现的 V2 功能先返回 400，之后逐项补齐。旧版 API、Gradio 和原版 Python 导入方式不列入后续适配计划。API v2 是接口版本，不表示支持全部 V2 模型家族。

后续优化以长时间后台运行、间歇生成语音为主要场景。桌宠是主要使用方，接口仍面向通用调用程序。现有默认启动、加载和推理行为保持不变；显式 `--runtime-mode managed` 提供休眠启动、提前唤醒、保活和推理进程回收。能保持现有行为的通用资源与加载优化，经验证后由两种模式共用；活动峰值和连续对话延迟分别测量。具体边界见[后台驻留与提前唤醒](background-runtime.md)。

模型元数据、执行后端、语言前端和发行 recipe 已分开，见[架构说明](architecture.md)。当前只有 CUDA / 日文实现，HTTP 与准备组件可独立选择；经典日文前端与声学工作进程有各自的解释器配置，也能共享同一运行目录。此次拆分不扩大已支持设备或语言，默认 direct / FP32 不变。

后续优先完成以下工作：

- 先补原版 `api_v2` 调用兼容：用固定上游契约检查请求字段、默认值、错误体、音频响应和模型／参考切换；同一请求分别调用原版与候选服务，区分协议、推理数值和听音结果。本轮已补 GET OpenAPI、切换错误体和单项批次分桶，后续还要对齐 `parallel_infer`、Top-p、语速、多参考、无转写、模式 2/3 及批量行为。缺失能力继续列入 [HTTP 清单](http-api.md)，不能用成功响应代替实现。
- 再接多语言：先提供英文处理器和离线词典，解决 `en` 与日英混合；再接中文 G2PW、BERT 和参考转写，之后补自动语言路由。每种语言验证 `text_lang`、`prompt_lang` 独立改变、A→B→A 连续切换及失败恢复。新增组件跟随 NVIDIA 整合包交付，AMD 和 Mac 暂不扩展。
- 验证可选控制模式：[后续单机测量](../research/notes/managed-refinement-20260922.md)已覆盖主存精简、H 档 HTTP 对照和标准档 100 次真实模型睡醒。总体 `staged` 仅由显式 `managed` 模式开放；继续测量不同提前量、H 档反复睡醒与数小时待机，再决定是否需要执行预热、CPU 权重缓存或调整保活默认值。
- 扩大 [Windows / NVIDIA 整合包](portable-bundle.md)验收：[1.961 GB 完整包](../research/notes/portable-compact-20260922.md)已在本机走通原始权重转换、新参考编码、缓存、搬迁及解压检查；继续补齐干净机器和音质验收。精简推理包继续保留。
- 补齐部署验证：在第二台干净机器验证模型转换、独立 ORT 组件、安装与首次请求，明确驱动和硬件范围。
- 完成质量验收：对四档配置检查长句内容、音色和自然度，保留 FP16 相对 FP32 的数值失败记录。
- 验证服务长期运行：覆盖重复请求、失败恢复、取消、模型切换和资源释放，并测量实际宿主的播放与取消行为。
- 精简准备组件：保持按需启动和 CPU 准备，减少上游导入链带来的额外依赖，补齐公共辅助权重的分发声明。
- 新设备后端暂缓：将来 CPU 需要补 GPT 并与已有 ORT CPU 声学串联；AMD 按 Windows 目标评估；Apple 从已有 MLX 实验完成公共 Runtime、转换及 macOS 发布适配。每个组合分别验收，不把未完成的名字加入能力清单。

中文整链、CPU / AMD / Apple 公共推理、其他模型家族、语义 token 流式和并行批量仍未完成。新增后端或语言要验证原始模型导入、新参考、目标文本、流式、取消、切换和睡醒，再纳入发行 recipe。2 GB 压缩目标继续用于当前 Windows 日文完整包；扩展组合分别记录依赖和实测体积，优先按需交付。

早期研究计划保留在[历史路线记录](https://github.com/Rvosy/SakuraTTS/blob/main/research/notes/roadmap-20260920.md)，其中的阶段状态和默认参数属于当时记录。
