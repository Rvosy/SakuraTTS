# Windows 声码器分块实验

更新日期：2026-09-20。设备为 Windows 11 / RTX 5060 8 GB，模型为 Sakura V2ProPlus。本轮在已筛查的 polyphase FP16 声学包上继续降低执行中的长句峰值，保留完整编码器和 reverse flow。分块仍是开发实验，尚未接入公开配置或完成音质验收。

## 方法与边界

`scripts/split_sovits_vocoder.py` 从实际声码器 `conv_pre` 输入处分开两张图。FP32 的切点是 `decoder_input`；FP16 的真实切点是 HALF `graph_output_cast_11`，导出时只改名为 `decoder_input`。原先用于诊断的 HALF→FLOAT Cast 不进入两分区之间，也没有新增计算精度转换。两分区的权重不重叠，条件 `ge` 的 HALF Cast 各自保留。

`scripts/vocoder_receptive_field.py` 从原始 ONNX 的真实算子和权重形状反推依赖。每个 latent 帧对应 640 个音频样本，内部块左右各需 11 个 latent 帧上下文。它同时覆盖中间层的有效范围：偏置和说话人条件会让隐层出现非零值，仅检查最底层输入的依赖并不充分。

块与真实句首、句尾相交时只取实际存在的帧，不向 latent 补零。块的中心输出按整数样本位置拼接，没有淡入淡出；全部波形重建后再由原函数归一化、追加一次 0.3 秒静音并转换 PCM。编码器和 flow 的非因果上下文没有截断，也没有更改 GPT、文本、噪声、采样或停止规则。

当前实现把完整 HALF latent 传回主存，再逐块送入声码器。这部分传输、每块调用、裁剪和拼接均计入耗时。它用于先验证分块收益，尚未实现跨 session 的 GPU I/O Binding，也不构成流式首包测量。

## 正确性证据

- 6 项独立 CPU 测试覆盖有符号区间运算、逐层依赖、640 个上采样相位、非零偏置与条件、JSON 溯源及不依赖 ONNX 的运行时加载。数值测试还证明了向 latent 补零会改变真实句首句尾。
- 原 FP32 四组导出样例共 24 项 CPU 拆图检查通过。4 组固定声学输入各执行 3 次，拆图整段和 128 帧分块都通过原始 `atol=1e-4, rtol=1e-5`，同时分别对照原整图和拆图整段。FP32 重复结果不总是逐位相同，保留这个现象。
- FP16 拆图整段与原整图的四组波形逐位一致。64、128、256、512 帧分块都通过运行前保存的工程筛查；分块结果仍有原严格容差失败，没有将它改报为严格等价。
- 额外 17 组形状输入包含 1–129 个语义 token、分块边界两侧和一组零噪声。64、128、256 帧分块各执行 51 次，均通过工程筛查，重复结果逐位一致。这些是边界诊断输入，不是有语义质量结论的语音样本。
- 256 帧的 latent 和 vocoder 两张图在 CUDA profiling 中均观察到 FP16 卷积，没有 CPU 神经计算事件。

分块专用门槛在 GPU 执行前写入报告：波形最大误差 ≤0.005、RMSE ≤0.0005、SNR ≥45 dB、频谱收敛误差 ≤1%、有效频点对数 RMS ≤0.3 dB。每个接缝前后各 640 个样本另查最大误差和 RMSE，同时保留此前的幅度门槛。它们只是工程回归筛查，不能代替人工听音或 ASR。

## 固定声学输入的时间与显存

以下时间是独立无资源采样进程中的热中位数，每组 5 次。范围为完整声学输入到 CPU 波形，包含 latent 往返与分块操作，不含 GPT、前端、PCM 转换和写盘。

| FP16 声学方式 | 短句 ms | 长句 ms | 多句 ms | 标点 ms |
| --- | ---: | ---: | ---: | ---: |
| 原整图 + arena 收缩 | 27.99 | 226.82 | 87.25 | 67.24 |
| 256 帧分块 + arena 收缩 | 28.35 | 214.19 | 92.21 | 71.41 |
| 512 帧分块 + arena 收缩 | 28.46 | 215.12 | 95.44 | 67.52 |

256 帧的长句在这一轮约快 12.64 ms，多句和标点略慢。64 与 128 帧初筛耗时更高，没有据此推广为默认。512 帧没有显示出比 256 帧更好的长句速度。

资源轮采用全卡 100 ms 采样，和计时进程分开。复测原整图初始 2156 MiB、峰值 2928 MiB、差值 772 MiB；256 帧初始 2171 MiB、峰值 2536 MiB、差值 365 MiB。此前一轮分别为 850 和 382 MiB。两轮均观察到明显峰值下降，但这些值包含桌面活动，也可能漏掉短峰，不能当作声学进程独占显存，更不能当作完整 TTS 显存。512 帧一轮差值为 477 MiB。

## 完整请求

`harness/windows_chunked_synthesis.py` 将相同的分块方式接入现有完整请求基准。它只替换声学加载器，使用共享进程，并保留经典日文前端工作进程。原整图对照也在同一个 Python 3.11 / ORT 1.19.2 共享进程环境重新运行。它不是公开运行时的默认路径，不能据此认为工作进程故障隔离已经验收。

两种 GPT 配置分别测量，每个计时轮为首次请求加四类文本各 3 次热请求；资源轮另跑首次请求加四类各 1 次。表中长句时间只来自无资源采样的计时轮。

| 共享进程配置 | 完整长音频 s | 原整图热长句 ms | 256 帧热长句 ms | 原整图 / 分块全卡峰值减初值 MiB |
| --- | ---: | ---: | ---: | ---: |
| GPT FP16 baseline attention，自然生成 | 25.46 | 2390.41 | 2361.33 | 1057 / 701 |
| GPT FP32 split-KV 256，固定官方随机输入回放 | 27.30 | 1588.27 | 1570.00 | 1407 / 1011 |

两组均使用相同的 polyphase FP16 声学权重并启用 arena 收缩。第一组两次资源采样的初始全卡用量均为 2162 MiB，峰值分别是 3219 和 2863 MiB。701 MiB 是这个配置、这些输入和这次采样的全卡差值，不能改称进程独占量，或宣布已经普遍达到 Lite 的 0.8 GB。

速度收益约为长句总耗时的 1%，短句和中等长度没有一致改善。自然生成短句中位数为 176.22→184.27 ms，标点 441.47→450.74 ms；固定回放短句 123.14→123.91 ms，多句 606.12→614.42 ms。本轮的主要收益是降低峰值，保留这些小幅回退，后续需要减少每块执行和拷贝的成本。

FP32 GPT 固定回放的音素、采样 token、语义 token、停止、索引和长度检查全部通过，但声学 FP16 的 PCM 仍未通过官方原始 FP32 容差，两种声学执行方式均保留 `replay_validation_failed`。分块候选应与同精度原整图分别对照，不能用总体 `completed` 状态代替质量检查。

逐个读取 WAV 后，两组各 13 对原整图/分块比较的请求契约全部一致，完整 PCM 和仅去掉固定尾部静音的语音段均通过原定工程门槛。每组各有 9 对未通过同精度原始数值容差，保留失败；同配置的计时/资源轮合计 20 对 PCM 逐位一致。`--chunk-frames 0` 的完整拆图对照另有 5 个请求，其 PCM 与原整图逐位一致。

10 个完整请求实验共核对 84 个实际 WAV。自然生成与固定回放分别检查了 21 和 24 个接缝，全部通过；相对同精度原整图的最大归一化 PCM 误差均为 0.0009765625，最低 SNR 分别约 61.91 和 61.99 dB。长句后卸载 GPT 和两张声学 session，再加载后的两次短句 PCM 均与首次短句逐位一致；报告中确实记录了两次声学加载。此结果不包含强杀共享进程后的宿主恢复。

## 实验入口和保留的失败

`harness/windows_vocoder_chunks.py` 分别提供原整图、拆图整段和分块运行。分块必须提供相同输入和执行环境的拆图整段对照；报告记录图、权重、输入、对照波形、执行源码和 RF JSON 的哈希。每次保存完整波形和一次转换的 PCM。`--record-baseline` 只记录原图形状对照，其检查含义是重复一致性，不是独立正确性验收。

最终 FP16 拆图包是 `outputs/windows-vocoder-chunks/fp16-split-v3`。第一次导出将小型 Reshape 形状张量外置，ONNX full check 失败；v2 在检查时加载完整张量后通过，但 ORT 1.19.2 仍无法直接加载这个文件。v3 将小张量内嵌、大权重外置，并对磁盘文件执行完整检查；保留失败目录，没有换用全量内嵌运行时绕过。

原始结果位于 `outputs/windows-vocoder-chunks`。普通探针使用 Python 3.11 + 独立 ORT 1.19.2，原整图也在相同环境重新运行；不能将其耗时直接归因于原 Python 3.9 声学工作进程中的单一改动。

最终单元回归共 185 项，183 项通过，2 项因 Windows 符号链接权限跳过。探针开发过程中补齐了幅度门槛、空输入拒绝和对照哈希检查；完整请求测量后又修复了源码变化/证据采集失败的退出状态及异常清理，这些改动没有改变声学计算。修复后的两次 GPU 短句冒烟通过，PCM 与修复前逐位相同。正式计时和资源数据仍取各自原始报告，没有用冒烟时间替换。

[实验数据](data/2026-09-20-windows-vocoder-chunks.json)保存各轮状态、输入/输出来源、严格失败、接缝检查、独立计时和资源摘要。完整声学探针的 27 份报告共记录 543 次执行，169 个保存的 NPZ 已独立核对波形和 PCM 哈希；未保存的重复轮只以运行报告为证据。汇总脚本保留在原始输出目录。

后续重点是复测完整请求的收益、接入声学工作进程并验证其生命周期，以及测量 GPU 内部传递 latent 的成本。公开默认、模型支持范围和质量状态继续保持原有记录。
