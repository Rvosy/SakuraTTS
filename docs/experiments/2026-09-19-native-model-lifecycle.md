# 日文完整请求的模型复用与状态释放

日期：2026-09-19。前一轮四条原始日文请求中，每次 GPT / SoVITS 加载及校验约耗时 0.40–0.42 秒。本轮比较调用方复用模型的收益，并检查保留权重时能否释放上一请求的 KV。

本轮使用独立 Harness，产品生成调用仍为 `prepare_text` 和 `synthesize_prepared`。先在 Harness 验证释放候选，再将相同操作落实为 `MLXGPT.release_request_state()`，由调用方显式选择。没有新增会话或后端框架。

## 对照条件

| 策略 | 请求之间保留什么 | 释放时机 |
|---|---|---|
| `request` | 不保留 GPT / SoVITS | 每条请求完成后卸载两者 |
| `resident` | GPT / SoVITS 权重和最后一条请求的 GPT KV | 一轮请求结束后卸载 |
| `resident-release-state` | GPT / SoVITS 权重 | 声学生成完成后清空 GPT 请求状态；一轮结束后卸载权重 |

三个策略每次都从原文重新创建、使用和关闭日文前端；每次前端关闭及请求完成时都执行相同的垃圾回收与 MLX 空闲缓存清理。驻留策略运行后续文本前端时，合成模型仍然驻留，这部分空间成本计入边界记录。pyopenjtalk 的 Nani / Sudachi 进程级缓存仍可能存在。

输入取自已通过的 `runs/20260919T141941.903341Z-native-text-speech-normal/`：原始报告句、短句、长句、标点句。原文、`ja` 模式、单片段 `cut0`、日文参考包、模型包、官方采样随机数和声学噪声保持一致。GPT 使用 CPU FP64 Prefill 与 GPU FP32 Decode；声学 encoder 为 CPU FP32，flow / decoder 为 GPU FP32，不启用 WeightNorm 折叠。

每个独立 worker 运行两轮，每轮结束真正卸载模型，随后重新加载。各轮交错运行四条输入，并在正序和反序间切换，覆盖长句后接短句。诊断与正常计时分开；诊断每轮每例调用两次，正常每轮每例首次一次、预热两次、测量五次。

## 重置与失败恢复

静态调用链中，`generate_semantic` 每次复制参考语义作为新 history，并从空 sampled 列表开始。`MLXGPT.prefill` 的 FP32 分支调用 `reset()`；本轮使用的 FP64 分支直接清空旧 KV、归零 length、重设 text_length，再从当前输入构建 KV。SoVITS 的声学计算使用局部张量，没有持久化请求历史。

因此 Harness 不在正常生成前额外重置对象，而是验证公开入口本身的行为。诊断组记录 Prefill 前后的位置状态；每次正常输出对照目标和拼接音素 / BERT、token、history、停止条件、语义、官方波形容差以及上一轮自有 PCM / 波形的逐位一致性。

最初三组对照的源码快照中，`resident-release-state` 仅在 Harness 内清空 `keys`、`values`、`length`、`text_length`、`prefill_profile`。公开方法采用相同的五字段赋值。不使用 `reset()` 释放，因为它会分配替代 KV。正常请求在声学生成完成后释放；诊断失败则在异常退出后释放。本轮不改变正常生成阶段顺序。

诊断每轮加入两次失败探针：声学 noise shape 错误，以及真实 Decode 容量错误。容量探针临时把容量设为当前 Prefill 长度加一，允许 Prefill 和一次 Decode，再由现有 guard 抛错；随后恢复原容量。两种失败都不得返回或保存音频，之后使用同一驻留实例运行原始短句并对照。正常计时进程不注入失败。

## 测量口径

正常请求计时包含前端创建、文本准备和关闭、公共生成入口、CPU 输出及 PCM 转换、GPT 位置 / KV 大小的标量检查、该策略的清理。标量检查没有增加 GPU 同步。`request` 同时包含每次模型校验、加载和卸载。驻留组的每轮加载及最终卸载单独计时；除稳态中位数外，另报告包含这些成本的每轮均摊时间。均摊值包含首次与预热请求，不当作稳态中位数。

初始运行时导入、准备阶段资源哈希、参考及金标读取、结果比较和磁盘写入不在请求计时内。每轮首条请求发生在已启动的 worker 中，不代表完整应用冷启动。

诊断记录生成完成且尚未清理、清理状态但尚未清理缓存、清理缓存后的空闲边界，以及最终卸载后的 MLX active / cache 和进程 RSS。边界不是阶段峰值。MLX allocator peak 只覆盖自身分配器；Apple 统一内存不能当作 NVIDIA 显存。RSS 包含 Harness、金标、基线输出及返回的 CPU 音频。

## 实际结果

三组正式诊断共完成 48 次正常请求及 12 次预期失败，三组正常计时完成 192 次请求，全部对照通过，六个进程退出码均为 0。每个驻留策略在两轮中都从失败状态恢复，并生成与基线逐位相同的原始短句。六组的四份 WAV 整文件相同，且与上一轮四份基线 WAV 相同。

| 策略 | 请求完成时 active | 清理后的空闲 active / cache | 每轮卸载后 active / cache |
|---|---:|---:|---:|
| `request` | 565.05 MiB | 0 / 0 MiB | 0 / 0 MiB |
| `resident` | 565.05 MiB | 565.05 / 0 MiB | 0 / 0 MiB |
| `resident-release-state` | 565.05 MiB | 469.05 / 0 MiB | 0 / 0 MiB |

释放请求状态使 MLX active 稳定减少 96 MiB，与保留的 KV 大小相同。三组 allocator peak 都约为 1721.21 MiB；本轮释放发生在生成后，没有降低生成峰值。诊断进程最大 RSS 分别为 1185.63、1187.42、1192.25 MiB，没有观察到 RSS 峰值改善。

正常请求每例有 10 个测量值，来自两轮各 5 次，以下为中位数：

| 原始样例 | 每次加载释放 | 保留模型 | 保留模型、释放请求 KV | 相对每次加载减少 |
|---|---:|---:|---:|---:|
| 原始报告句 | 1.496 s | 1.066 s | 1.070 s | 0.426 s，28.5% |
| 短句 | 0.772 s | 0.344 s | 0.344 s | 0.428 s，55.4% |
| 长句 | 3.662 s | 3.219 s | 3.219 s | 0.443 s，12.1% |
| 标点句 | 2.184 s | 1.765 s | 1.773 s | 0.411 s，18.8% |

最后一列比较 `resident-release-state` 与 `request`。释放状态组与保留 KV 组的中位数差在本轮约为 -0.2 至 7.5 ms，没有抵消模型复用带来的加载收益。完整输出仍为 PCM，不是流式首包。

释放状态组的 RTF 依次为 0.223、0.374、0.216、0.210，分母使用 4.80、0.92、14.92、8.44 秒的音频主体；包含末尾 0.3 秒静音的 PCM 时长则为 5.10、1.22、15.22、8.74 秒。

驻留组每轮加载仍需 0.419–0.429 秒，最终卸载约 0.008–0.010 秒。把加载和卸载纳入每轮 32 次请求，并包括首次及预热调用后，三种策略两轮的请求均摊分别为：

| 策略 | 第一轮均摊 | 第二轮均摊 |
|---|---:|---:|
| `request` | 2.035 s | 2.028 s |
| `resident` | 1.618 s | 1.617 s |
| `resident-release-state` | 1.624 s | 1.622 s |

这支持调用方在连续请求间保留模型、生成后释放当前 KV；需要更低空闲常驻时，仍可卸载两份模型。

公开 `release_request_state()` 的额外真实回归完成 16 次请求、4 次预期失败及其同实例恢复，另有 20 次重复释放与释放后 Decode 拒绝检查，全部通过，进程退出码为 0。重复释放不会创建替代 KV；释放后 Decode 明确报 `Call prefill before decode`，重新 Prefill 后的 token / 波形仍相同。公开方法组空闲 active 为 469.05 MiB、cache 为 0，两次完整卸载后 active / cache 均为 0；四份 WAV 与六组对照相同。当前相关源码与该次实测快照逐字相同。

RSS 并不随 MLX active 等比例下降。诊断空闲边界的 RSS 中位数分别为 863.46、1004.11、1003.53 MiB，第二轮完整卸载后分别为 574.89、944.05、949.97 MiB。这些数据还受进程级缓存和内存分配器保留影响，本轮没有把 MLX 清零解释为进程资源全部释放。

本轮没有新 ASR 或人工试听。原始报告句的 WAV 保持此前用户听过的字节内容，其已有反馈仍适用；另外三条日文的内容和音色没有新增验收。Windows / CUDA 尚未运行。
