# Windows 声码器 GPU latent 传递实验

日期：2026-09-20。Windows 11 / RTX 5060 8 GB，Sakura V2ProPlus，polyphase FP16 声学包，256 帧声码器分块，两张 ORT session 均启用请求后 arena 收缩。

本轮去掉了两张图之间的 latent 主机往返，但没有测到速度或显存收益。独立工作进程的分块候选继续使用已有的主机传递方式，GPU latent 保留为开发实验。

## 实现

`harness/windows_device_latent.py` 让第一张图通过 ORT I/O Binding 直接输出 CUDA latent。内部块是 `[1, 192, T]` 张量的时间切片；各通道之间仍有原整句的跨度，不能只偏移指针就当作连续张量传入声码器。实现用 `cudaMemcpy2D` 将每块打包到一个请求内复用的 CUDA 缓冲区，再通过指针绑定输入。真实句首、句尾和 11 帧上下文规则沿用[分块实验](2026-09-20-windows-vocoder-chunks.md)。

打包缓冲区和条件 `ge` 使用请求内的 `cudaMalloc` / `cudaFree`，没有使用 OrtValue 工厂的进程全局 arena。两张 session 和外部 CUDA 调用之间显式同步。声码器仍返回完整块的 CPU 波形，裁掉 halo 后拼接；归一化和 PCM 转换方式保持一致。该实现不需要 CuPy、内核编译或运行时 ONNX 图处理。

## 数值检查

GPU 传递是同精度执行方式的变化，因此单独要求它与已验证的主机分块波形逐位一致。原整图和分块间已有的 FP16 严格差异仍保留，不能用传递检查通过覆盖它们。

四组常规输入、17 组边界输入、profiling、独立计时及资源轮合计记录 111 次 GPU 传递声学执行；相应的主机计时与资源轮记录 36 次执行。GPU 传递检查和重复一致性均通过。保存的首轮 NPZ 另由 CPU 脚本读取，对照各次记录的波形和 PCM 哈希。未保存的重复输出以当次运行报告为证据。

CPU 测试用独立 NumPy 切片核对 558 个矩形切片，覆盖 192 个通道及 2 / 4 字节元素，同时检查源数据不变、目标边界不越界、延迟拷贝完成前必须同步，以及拷贝和同步错误的传播。测试不加载 CUDA DLL。

## 性能

时间来自各自独立、无持续资源采样的进程，每组 5 次热请求的中位数。范围为声学输入到完整 CPU 波形，包含打包、同步、拷贝、分块拼接和请求内缓冲区释放，不包含 GPT、前端或完整 TTS 请求。

| 输入 | 主机 latent ms | GPU latent ms |
| --- | ---: | ---: |
| 短句 | 29.053 | 30.171 |
| 长句 | 215.405 | 218.577 |
| 多句 | 92.690 | 93.177 |
| 标点 | 71.674 | 72.115 |

独立资源轮的全卡初值均为 2121 MiB，主机传递峰值 2492 MiB，GPU 传递峰值 2496 MiB，差值分别为 371 和 375 MiB。这是包含桌面活动的 100 ms 全卡采样，可能漏掉短峰，不能解释为进程独占显存。两项指标都没有显示本候选值得启用。

长句包含 1350 个 latent 帧、6 块。应用层明确安排的传输中，消除了 518400 字节的 latent D2H；第一张图输入 H2D 为 1050884 字节，声码器条件 H2D 为 4096 字节，块打包 D2D 为 560640 字节，打包缓冲区为 106752 字节，含 halo 的波形 D2H 为 3737600 字节。这些是逻辑字节数，不是实际 PCIe 流量测量。

两张图的 ORT profile 未观察到 CPU 神经计算回退。但 ORT profile 在主机传递对照中也可能不记录 Memcpy 事件，不能凭“零 Memcpy 事件”宣称没有拷贝。本机未使用 CUPTI 或 Nsight 的硬件传输计数。

## 证据与后续

原始目录为 `outputs/windows-vocoder-device`；[独立汇总](data/2026-09-20-windows-vocoder-device.json)保留输入、模型、图、权重、RF、对照和源码哈希，各次严格结果、逐位传递结果、原始采样摘要及测量边界。早期检查 / profiling 与后来的计时 / 资源轮存在 harness 修订，成对性能对照使用相同修订，每轮均未在执行中修改源码。实验结束后仅将模块说明中的 OrtValue 改成实际使用的 CUDA 缓冲区，没有改变计算。

本轮没有证明减少 latent 拷贝能改善总耗时。后续先完成主机分块在私有工作进程中的完整请求和生命周期验证，再依据剩余计算热点选择优化。若将来重新尝试 GPU 传递，需要有降低同步或分配成本的新实现依据，不重复运行相同方案。
