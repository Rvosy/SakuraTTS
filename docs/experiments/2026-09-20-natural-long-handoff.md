## 新长文发现

新增 590 字自然日文，保存在 `harness/cases/japanese_long_validation.json`。原四条回归不变。所有候选使用同一原文、朱雀院红叶 V2Pro 和参考 B；不会根据识别结果改写文本。原始记录在 `SakuraTTS-References/runs/20260919T183907.425521Z-natural-japanese-long-suite/`。

`cut0` 得到 478 / 112 字两片。自有 NumPy seed 1234、容量 4096 生成 826 / 464 个采样 token，均因 EOS 停止，有效波形 51.52 秒。离线 ASR 对首片中段大量识别不匹配，末片相对完整。因此正常 EOS 和完整文件不能作为内容验收。

同条件官方 MPS 诊断在长片 Decode 中明显变慢，主机交换空间使用量超过 12 GiB。保留快照后中断：官方 worker 返回 -2，控制器进程返回 254。旧 Harness 的 JSON 仍写着 `running`，该字段已由旁边的真实退出记录和 `cut0-resource-interruption.json` 纠正为未完成；未改写历史文件。没有完整官方结果，不能据此确定长文问题来自自有计算还是上游行为。快照也不能称为请求显存峰值。

## 显式 cut2 候选

新增 `--text-split-method cut2` 和 Python 的 `prepare_text_request(..., split_method="cut2")`。默认仍为 `cut0`，原单片接口保持原行为。两种方法都记录原文和实际分句方法，不自动回退。`cut2` 是固定官方规则：累计完整子句超过 50 字符后分组，末组少于 50 字符时合并，再执行外层换行和短片规则；不保证每片固定长度或容量上限。

同一 590 字原文得到 69 / 80 / 86 / 84 / 78 / 81 / 112 字七片。自有 seed 1234、默认容量 1024 正常结束，采样 2079 步、有效波形 82.88 秒。ASR 能识别更多对应段落，但没有识别出第一片的第二句，其他位置也有遗漏和不匹配。此例仍未通过内容完整验收；不把不同分句方法的耗时或音频长度差异算作同能力加速。

官方 `cut2` MPS 诊断完成前三片，观察到 932 个采样步骤；为结束持续占用并切换研发平台，随后中断。新 Harness 保存 `interrupted`、已观察进度和退出码 130。全请求官方捕获、自有固定随机数回放和人工试听仍待完成。因此 `cut2` 只保留为显式实验入口，不加入已验收兼容范围。

两份 ASR 使用既有离线 Whisper-small，不提供目标转录提示。结果位于 `20260919T184334.033616Z-asr-review` 和 `20260919T185038.800721Z-asr-review`。ASR 不判断音色、助词实际读音，也不能单独区分 TTS 内容缺失与识别错误。

本轮完整单元测试实际运行 60 项，通过；它们不替代尚未完成的自然长文官方模型对照。

- 44 项完整分句链与固定官方抽取函数一致，覆盖空、短、内部换行、长度边界和 590 字样例。
- 六个真实 CLI 进程通过预期检查：原四条默认 `cut0` WAV 逐字节相同；自然长文 `cut2` 完成；七片限额样例逐片生成后返回 2。

参数与导入前中断检查位于 `20260919T184406.083706Z-cut2-options-interrupt-check`；44 项分句对照及实际 CLI SIGINT 注入位于 `20260919T184733.962699Z-cli-sigint-record`。自然长文套件保留冻结源码、原始日志、CLI / ASR 命令及退出码。新样例没有人工试听结论。

## 下一平台的顺序

先固定 Windows GPU、显存、驱动和开发环境，再从四例便携包建立 CUDA 正确性对照。当前概率 / MRTE 超差保持原阈值，不因换平台豁免。完成基础重放后再接原始日文、参考包与完整请求，复跑本轮自然长文的官方与自有同条件对照，确认失败来自何处。

资源测量覆盖空闲常驻、请求峰值和卸载；性能使用无诊断运行，另测冷启动和热请求。根据真实热点选择一条生产 CUDA 路径，再评估 FP16、KV 更新、传输和声学工作区。Mac 的统一内存或这两次中断不能替代 Windows 数据。
