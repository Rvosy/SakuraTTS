# 日文请求按阶段加载 GPT 与 SoVITS

日期：2026-09-19。上一轮已经在声学生成前释放 GPT 请求 KV，但 GPT 权重仍和声学工作区同时驻留。本轮将公开合成接口拆成语义、声学两个阶段，让调用方在语义完成后卸载 GPT，再加载 SoVITS。模型计算、采样和原始日文不变。

`generate_prepared_semantic` 返回目标音素快照、绑定的参考条件、生成历史和继续使用的 NumPy RNG，不保存模型或回调。`synthesize_acoustic` 直接使用这些条件，不能另传参考；执行前检查参考身份和声学模型身份。已有 `synthesize_prepared` 仍组合调用两阶段。

模型加载、卸载和缓存清理由调用方负责。公开接口的阶段计算时间排除中间加载和等待，完整请求另计。分阶段接口尚不提供生成中途取消。

## 同条件对照

两组都是每次请求加载、卸载 GPT 和 SoVITS 各一次，语义完成后都释放 KV。`simultaneous` 先加载两模型，生成波形后一起卸载；`staged` 在语义完成后删除 GPT 引用、收集垃圾、清理空闲缓存并同步，然后加载 SoVITS。没有把常驻模型与每次重载的耗时混为同一基线。

沿用四条原始日文、相同参考包、官方采样 draw 和声学 noise，真实前端从原文准备输入。CPU FP64 GPT Prefill、GPU FP32 Decode、CPU FP32 encoder 和 GPU FP32 flow / decoder 保持不变，WeightNorm 折叠仍关闭。

诊断和正常计时各用独立进程，两组使用相同源码快照。诊断每组两轮，每轮每例首次和重复各一次；正常每组两轮，每轮每例首次一次、预热一次、测量三次。两轮交替正反序执行。

诊断每轮触发一次真实 Decode 容量错误和一次声学 noise shape 错误，保存原始 traceback 字符串，检查没有音频输出，清理后重新加载并恢复原始短句。分阶段路径在语义失败后不加载无用 SoVITS。弱引用检查模型对象是否真正销毁，诊断声学对象不持有 GPT 强引用。

每请求开始前重置 MLX allocator peak，包含前端、两次模型加载、生成和清理。同步边界的 active、cache 和 RSS 单列；边界快照不当作阶段峰值，OS maxrss 只表示整个进程生命周期的最大 RSS。正常模式不使用诊断子类，不采样或重置峰值，完整耗时包含两模型的校验、加载与卸载。前置资源校验、金标读取和输出比较不在请求计时内。

## 资源结果

两组诊断各完成 16 次成功请求和 4 次预期失败，检查全部通过。固定生成历史、token、停止原因、语义切片、目标及拼接特征通过对照；波形通过原官方容差，波形 / PCM 与旧自有基线逐位相同，WAV 整文件也相同。

下表取每条样例四次成功诊断中的最大请求分配器峰值，包含该请求的模型加载：

| 原始样例 | 同时加载 | 分阶段加载 | 减少 |
|---|---:|---:|---:|
| 原始报告句 | 845.85 MiB | 541.96 MiB | 303.89 MiB |
| 短句 | 598.94 MiB | 416.40 MiB | 182.54 MiB |
| 长句 | 1625.21 MiB | 1321.32 MiB | 303.90 MiB |
| 标点句 | 1126.12 MiB | 822.22 MiB | 303.89 MiB |

长句最大值减少约 18.70%。短句没有减少完整的 GPT 权重大小，因为提前卸载后，整请求的最高点可能转移到另一个阶段；不能把阶段快照的差值直接当成每请求峰值收益。

分阶段路径在 GPT 卸载后、SoVITS 加载前的 active / cache 均为 0，GPT 弱引用也已失效。声学入口 active 从约 469.05 降至 165.15 MiB；两组每请求最终完整卸载后 active / cache 都是 0。进程和系统仍保留其他资源，不能把它解释为进程内存归零。

诊断进程生命周期最高 RSS 从 1164.92 降至 889.11 MiB，少 275.81 MiB。这是本轮两个进程的 OS 统计，包含 Harness 与金标；它不是请求区间 RSS 峰值，更不是 NVIDIA 显存。正常计时进程的 RSS 另行记录。

## 正常耗时与采用范围

正常两组各完成 40 次请求，连同诊断共 112 次成功请求和 8 次预期失败，四个进程退出码均为 0。每例中位数来自两轮共六次测量，包含前端、两模型加载、生成和卸载：

| 原始样例 | 同时加载 | 分阶段加载 | 分阶段减去同时加载 |
|---|---:|---:|---:|
| 原始报告句 | 1.5438 s | 1.5251 s | −18.7 ms |
| 短句 | 0.7863 s | 0.7868 s | +0.5 ms |
| 长句 | 3.7357 s | 3.7871 s | +51.5 ms |
| 标点句 | 2.2805 s | 2.3079 s | +27.4 ms |

长句与标点句本轮慢约 1.4% 和 1.2%，不把此改动称为加速。分阶段 RTF 依次为 0.318、0.855、0.254、0.273，分母为音频主体，不含末尾静音。包含首次与预热的两轮均摊请求耗时，对照为 2.0992 / 2.0966 秒，候选为 2.1137 / 2.1123 秒。正常进程生命周期最高 RSS 从 1192.50 降至 889.33 MiB。

CLI 默认采用 `staged`，保留 `--model-policy simultaneous` 供对照。理由是同样每次加载各模型一次时，资源峰值下降明确，本轮速度代价较小。需要连续发声的 Python 调用方仍可选择既有权重常驻策略；它的请求延迟和空闲成本不同，不用本表替代常驻策略的实测结果。没有减少模型能力或更改精度。

## 独立随机命令行

CLI 增加 `--model-policy simultaneous|staged`。两种策略各运行 NumPy seed 0 和 1，共四个独立进程，退出码均为 0。每份 WAV 与旧普通入口的对应 seed 文件逐字节相同；原文、规范化、音素、生成数量、停止原因和返回 index 相同。旧 JSON 没有保存完整 token ID，因此这组只声称生成摘要和音频相同，不声称直接比过完整 token 序列。

改为默认分阶段后，又在不传 `--model-policy` 的真实 CLI 进程中验证 seed 0，退出码 0、策略记录为 `staged`，WAV 与显式分阶段及旧基线相同。该次用于验证默认入口，不增加速度结论。

运行没有导入 Torch、Transformers 或中文模块。未新增 ASR 和人工试听，已存在的自由采样 ASR 证据仅通过相同 WAV 字节关联；这两个 seed 的人工试听仍待反馈。
