# 在声学生成前释放 GPT 请求状态

日期：2026-09-19。上一轮确认生成后释放 GPT KV 可使空闲 MLX active 减少 96 MiB，但生成峰值没有变化。本轮将这一步提前到语义生成结束后、声学准备开始前，保留相同的 GPT / SoVITS 权重和计算顺序。

`synthesize_prepared(..., release_gpt_state=True)` 显式启用提前释放，默认仍为 `False`。语义生成在 `try/finally` 中调用，正常返回或语义异常后都释放 GPT 请求状态，然后才准备声学噪声并调用 SoVITS。入口前置验证失败不属于这段释放承诺。

返回的 token、history 和 semantic 都是 NumPy 数据。GPT logits 已求值并复制到 NumPy，SoVITS 再独立建立声学图，因此不额外复制 semantic，也不保留 GPT KV 供声学阶段使用。

## 实验条件

对照组 `resident-release-state` 在整条语音请求完成后释放 KV；候选组 `resident-release-before-acoustic` 调用新参数，声学之前释放。两组仍在每请求结束时清理空闲缓存，并在每轮结束真正卸载模型。产品释放方法自身不清理 MLX cache。

沿用上一轮四条原始日文、相同参考包、官方随机数和声学噪声。固定 `ja`、单片段 `cut0`、CPU FP64 GPT Prefill、GPU FP32 Decode、CPU FP32 声学 encoder、GPU FP32 flow / decoder，不折叠 WeightNorm。

两组使用同一份当前源码，各开诊断与正常进程。每进程两轮，交替正反序运行四条输入，覆盖长句后接短句。诊断每轮每例两次；正常每轮每例首次一次、预热一次、测量三次。

诊断记录 Prefill、释放前后及声学入口的 GPT 状态；候选必须在声学入口前已清空请求状态。每轮还触发一次真实 Decode 容量错误和一次声学 noise shape 错误，记录完整异常堆栈，确认不产生音频，再用同一模型重试原始短句。候选失败后状态必须为空；重复释放后 Decode 必须明确拒绝，重新 Prefill 后输出必须恢复。

两组检查规范化文本、目标和拼接音素 / BERT、token、history、停止 index / 原因、semantic、官方波形容差及原自有波形 / PCM 逐位一致性。目标内容不从历史特征注入产品。

## 计量边界

诊断在每次请求开始前重置 MLX allocator peak，结束后记录该次峰值，并另取整组请求最大值。计数从已驻留的权重开始，包含本次前端和生成，但不含每轮独立模型加载。声学入口和请求完成处是同步边界快照，不把它们称为阶段峰值。RSS 仅有边界样本及进程生命周期最大值，不称为请求 RSS 峰值。

正常计时不重置或采样请求峰值，也不使用诊断子类。请求总耗时仍含每次前端创建 / 关闭、生成、CPU 输出 / PCM 转换及清理。`semantic_seconds` 包含新参数触发的释放成本，`acoustic_seconds` 不包含这一步。驻留权重加载及最终卸载单独记录，并纳入每轮均摊。

MLX active、cache 和 allocator peak 分开记录，都是 Apple 统一内存下的分配器口径，不代表 NVIDIA 显存或总系统峰值。请求状态字段为空不表示异常处理期间全部局部张量已经销毁；异常只保存为类型、文本和 traceback 字符串，不持有 traceback 对象。

## 结果

`tests/test_synthesis.py` 的 10 项 NumPy 边界测试通过，其中新增检查覆盖声学前释放顺序、语义异常后释放且不生成音频、默认参数保留调用方的状态寿命。复现命令为 `../SakuraTTS-References/.venv-japanese-macos/bin/python -m unittest discover -s tests -p test_synthesis.py -v`。这些测试不替代下列真实模型对照。

两组诊断各完成 16 次成功请求和 4 次预期失败，正常两组各完成 40 次请求，共 112 次成功请求和 8 次预期失败，全部通过，四个进程退出码均为 0。候选在声学入口的 GPT 状态为空；容量错误发生前的长度确实到达 Prefill 长度加一，随后由产品 `finally` 清空，再使用同一实例恢复原始短句。四组 WAV 整文件相同，并与上一轮及原基线相同。

下面取每例 4 次成功诊断请求中的最大 MLX allocator peak，与本轮相同口径的新对照比较：

| 原始样例 | 请求完成后释放 | 声学前释放 | 减少 |
|---|---:|---:|---:|
| 原始报告句 | 941.85 MiB | 845.85 MiB | 96.00 MiB |
| 短句 | 694.84 MiB | 598.94 MiB | 95.91 MiB |
| 长句 | 1721.21 MiB | 1625.21 MiB | 96.00 MiB |
| 标点句 | 1222.12 MiB | 1126.12 MiB | 96.00 MiB |

整组请求最大值减少 96 MiB，约 5.58%。这里没有把旧实验的全进程 high-water 当作逐请求峰值。

声学入口的 active 从 565.05 降至 469.05 MiB，但空闲 cache 从约 22.10–43.96 增至 118.12–139.96 MiB。提前释放的块仍由分配器缓存，可供后续计算复用；这不是把 96 MiB 立即交还系统的证据。两组诊断进程最大 RSS 为 1186.72、1187.48 MiB，没有显示总 RSS 峰值下降。

请求结束清理后，两组空闲 active / cache 都是 469.05 / 0 MiB；每轮完整卸载后都为 0 / 0 MiB。第二轮卸载后的 RSS 分别为 944.72、944.97 MiB，不能把 MLX 清零解释为进程内存全部释放。

正常请求每例有 6 个测量值，来自两轮各 3 次，下面取中位数：

| 原始样例 | 请求完成后释放 | 声学前释放 | 增加 |
|---|---:|---:|---:|
| 原始报告句 | 1.0563 s | 1.0589 s | 2.6 ms |
| 短句 | 0.3396 s | 0.3416 s | 2.0 ms |
| 长句 | 3.1882 s | 3.2042 s | 16.0 ms |
| 标点句 | 1.7536 s | 1.7586 s | 5.0 ms |

本轮候选中位数高约 0.25–0.59%，不把提前释放称为加速。候选 RTF 依次为 0.221、0.371、0.215、0.208，分母使用 4.80、0.92、14.92、8.44 秒的音频主体，不含末尾 0.3 秒静音。

把每轮加载及卸载计入每轮 20 次请求，并包含首次与预热后，对照两轮请求均摊为 1.6125、1.6089 秒，候选为 1.6215、1.6164 秒。正常进程生命周期最大 RSS 分别为 1188.41、1189.42 MiB，同样没有显示改善。

结果支持完整 PCM CLI 显式传 `release_gpt_state=True`：它不需要在语义结果返回后继续使用原 GPT Decode 状态，提前释放保持输出并降低本轮 allocator active 峰值。公共 API 默认仍为 `False`，调用方明确选择生命周期。CLI 对外入口的[单次 seed 0 回归](2026-09-19-japanese-cli-early-release.md)另记，WAV 与旧文件逐字节相同，本轮没有把它算入通过数量。

本轮没有新增 ASR 或人工试听。原始报告句与此前已试听音频保持相同字节；另外三条的内容和音色没有新增验收。Windows / CUDA 与实际独立显存尚未验证。
