# G2PW 文本到拼音的独立闭环

日期：2026-09-19。自有 `G2PW` 已把文本准备、独立 tokenizer、NumPy 输入打包和 CPU ONNX Session 接通。27 组输入的完整拼音、`None`、异常、模型标签和置信度与固定官方路径一致，353 个输入及概率数组逐位相同。官方、自有两个独立进程均正常退出。

本轮到 G2PW 拼音为止。中文分词、多音词修正、变调、儿化、音素、`word2ph` 和特征 BERT 尚未接入这个入口，不能把结果当成完整中文前端通过。

## 薄接口与模型配置

新增 `src/sakuratts/g2pw.py`：

```python
engine = G2PW(resource_dir, tokenizer_json, model_path)
pinyins = engine(sentences)
engine.close()
```

接口组合现有 `G2PWText`、`ChineseBertTokenizer`、`G2PWInputs` 和 `G2PWSession`。构造时加载当前已验证的 G2PW 1.1 模型；调用中不加载其他模型，也不下载资源。当前配置对应官方 `use_mask=True, use_char_phoneme=False`，没有扩展到其他 G2PW 模型配置。

调用顺序按固定官方 `onnx_api.py.__call__` 保留：

1. OpenCC、查询上下文和逐字 partial 准备完成后，无查询直接返回 partials。
2. 原始完整多音字表的 8,021 行构建模型元数据，得到 3,582 个字符和 1,305 个标签。不能用文本准备时排除特殊字后的 3,563 字集合构建模型 ID。
3. 输入打包明确使用 `window_size=None`。模型配置文件中的 32 字窗口不适用于这条官方调用路径；默认文本上下文仍在前一步按 16 字规则处理。
4. 输入打包返回空字典时直接返回 partials；正常输入交给默认句子去重 Session。传入去重的仍是准备阶段返回的上下文文本。
5. 标签按原注音转换表还原拼音，再按 sentence ID 和完整句子中的结果位置填回。

构造阶段仍会加载 Session，无查询分支避免的是模型调用。本次未添加延迟加载、进程管理或缓存策略。

`"" → [[]]`、`[] → []`、`"天" → [["tian1"]]` 均直接返回，实际 Session 调用数为 0。另用显式诊断故障让 tokenizer 抛错，确认两侧输入打包都返回空字典并保留 `[["ni3", None, "。"]]`，没有调用模型或擅自补拼音。这是错误路径探针，不是自然文本上的质量结论。

## 未映射标签与长句边界

对全部 1,305 个标签另做纯函数映射检查，两侧结果相同。以下 8 个标签均打印原警告并返回 `None`：

```text
ㄈㄨㄥ4  ㄉㄧㄤ1  ㄌㄩㄢ2  ㄌㄩㄢ3  ㄌㄩㄣ2  ㄍㄧ2  ㄝ4  ㄩㄤ4
```

这反映的是原映射表边界，并不说明模型在本轮文本中选中了这 8 个标签。`chinese2` 直接调用内部 G2PW，绕过 `UltimateConverter` 的额外回退，因此组合层没有增加 PyPinyin 兜底。

超过 510 词元时，官方按原上下文去重与查询相关截断之间的[已知边界](2026-09-19-g2pw-dedup-boundary.md)继续保留。511 / 600 字的拼音、输入和默认去重调用结果与官方一致，不据此判定该边界的实际读法正确，也没有改变其行为。

## 诊断开销与资源边界

每次调用都保存准备结果、输入数组和模型概率，属于诊断路径。五组实际中文的自有单次耗时约 7.75–70.84 ms；没有独立的多次正常请求测量，不据此声称速度提升或完整 TTS 延迟。

流式文件校验后的复核轮中，自有进程构造结束 RSS 为 1447.55 MiB，完成全部诊断后为 1468.53 MiB，关闭 Session 并 GC 后为 573.53 MiB；相应官方值为 1518.75、1539.33、639.05 MiB。这些边界包含文本依赖、字符表和诊断对象，不能与仅加载 Session 的旧实验直接比较成优化收益。OS 生命周期最大值另存于 JSON；边界不是阶段峰值，CPU RSS 也不是 GPU 显存。

首次运行的 Harness 用 `read_bytes()` 校验 635 MB 模型，造成显著的校验临时内存。随后仅将 Harness 哈希改为分块读取，另建运行复核；两轮两侧全部输出和数组都逐位相同，旧轮保留。上面的资源数字只引用后者。这个改动没有改变自有运行时的模型或计算。

关闭 Session 后 RSS 仍明显高于初始值，本轮没有解释其全部来源。现阶段保持显式构造与关闭接口，完整请求生命周期和正常时延仍需单独测量。
