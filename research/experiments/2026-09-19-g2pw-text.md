# G2PW 查询准备移入自有前端

日期：2026-09-19。新增 `src/sakuratts/frontend/g2pw_text.py`，在不加载模型的进程里完成 G2PW 查询准备。与固定官方源码对照的 25 组输入中，23 组输出完全一致，另 2 组超出当前输入范围的文本保留相同 `IndexError`。本轮没有接入 ONNX 推理，也没有移植中文变调、分词或完整音素输出。

## 实际调用条件

固定官方提交为 `48b1a0169a28582a8984402f82cf438d3bfa6aca`。`chinese2.g2p()` 先按 `! ? … , . -` 分段，`_g2p()` 再删除每段的 ASCII 字母并过滤空段，一次调用 `g2pw._g2pw(batch_inputs)`。这条路径绕过 `G2PWPinyin.Converter` 的外层逐词转换，不能把它当成当前中文入口。

该实例使用拼音输出、OpenCC `s2tw` 和默认 16 字上下文。流程是先转台湾繁体，再用固定 `char_convert.py` 的逐字繁转简表生成 PyPinyin 回退输入；后一步没有改成 OpenCC 的其他模式。PyPinyin 参数保持 `Style.TONE3, neutral_tone_with_five=True`。

当前原始文本清洗、分段仍由上游完成。自有模块接收的是此调用点的批量中文片段，不对原始混合语言句子承诺完整支持。

## 接口和保留的语义

```python
builder = G2PWText(resource_dir, context_chars=16, enable_opencc=True)
texts, model_positions, result_positions, sentence_ids, partials = builder.prepare(sentences)
```

`sentences` 可为单字符串或字符串列表。返回值对应官方 `_prepare_data()` 的五项结果；每个 `partials` 保留与转换后字符等长的槽位，待模型判断的多音字为 `None`。

- 使用原 19 字多音排除集和 `似、攢` 单音排除集。顺序保持 OpenCC 转换在前，不能按原输入字形提前排除。例如原输入的“听”转换后为“聽”，实际是否进入查询仍按转换后的字形决定。
- 单音字走原注音到拼音表，其余字符使用 PyPinyin 回退。官方 `char_bopomofo_dict` 的两个分支执行完全相同的回退表达式，自有路径合并这两个分支，不需要载入该额外表。
- 默认上下文从首个多音字前 16 字延伸到末个多音字后 16 字，同一句的查询共享该片段。测试中两个相隔较远的查询保留 74 字上下文，局部位置为 16、57；没有改成每个查询独立截取。
- 保留原完整结果位置、上下文内查询位置、句子 ID 和批量顺序。`context_chars=0` 使用整句；OpenCC 转换后的长度断言仍保留。

本模块没有执行 tokenizer、510 token 截断或句子去重。509、510、511 和 600 字测试的原句和查询位置在这一阶段完全保留，[已记录的长文本去重边界](2026-09-19-g2pw-dedup-boundary.md)没有变化。

## 同输入对照

`research/tools/g2pw_text_equivalence.py` 从固定官方源码抽取 `_prepare_data()` 和注音转换函数作为 oracle，使用独立官方环境和无 Torch 运行环境分别执行。它不导入上游包初始化，也不构造 ONNX Session。官方排除集直接从该提交的 AST 读取，避免用自有常量充当预期值。

五组已保存的中文规范化文本先经过官方 `chinese2.g2p()` 的实际分段表达式，再保留 `_g2p()` 的去 ASCII / 过滤空段步骤。这五组包括用户中文样例、中文长句、中文标点和混合中英的两段中文，共产生 68 个查询、183 个逐字 partial 槽位。五项返回值全部一致。

其余输入覆盖简繁同句、特殊排除字、没有模型查询的单音字、标点、未知字符、扩展区汉字、空字符串 / 空批量、多个句子、单查询 / 跨查询上下文、长句边界，以及关闭上下文裁剪和关闭 OpenCC。所有成功结果均按完整列表比较，不只核对长度或查询数量。

`你好ABC。` 和 `你好?!` 在官方准备函数中因 PyPinyin 对连续非汉字分组而发生 `IndexError: list index out of range`，自有路径保留相同异常类型与原文。正常 `chinese2` 调用会先处理字母和分段；这两条用于记录模块输入边界，没有通过补空值或逐字符改写来掩盖异常。

两个进程均正常退出。自有进程实际未导入 Torch、Transformers、ONNX Runtime 或 MLX。测试仅覆盖文本准备和无需模型的拼音槽位，不代表模型预测的多音字拼音、中文变调或最终发音已经通过。

## 资源和依赖

运行环境新增两个固定版本：`opencc-python-reimplemented==0.1.7`、`pypinyin==0.55.0`，与官方环境一致。安装前后 `pip check` 均通过，包清单只增加这两个包，没有引入 Torch。版本已加入 `requirements/mlx-candidate.txt`。

新的资源目录保存原多音字表、单音字表、注音到拼音表和从固定源码导出的繁转简映射，连同来源清单、许可证和通知共 416,103 字节。原模型、原表和历史结果未修改。资源放在参考目录，自有源码运行时不导入官方 Python 文件；验证 Harness 才使用保存的官方源码。

保留 PaddlePaddle 的字符表版权和 Apache-2.0 通知，以及 GPT-SoVITS 的 MIT 文本。实际安装包的 PyPinyin MIT、OpenCC Apache 许可证和字典 NOTICE 已复制到 `docs/third-party/`，包内文本、代码和字典哈希保存在本轮证据中。G2PW 模型表的完整再分发许可链仍未补齐，该资源包只作为本地兼容实验产物。

本轮没有正常请求的性能对照或内存峰值测量。它完成的是去掉 G2PW 文本准备对官方包初始化的依赖；不能将这部分改动描述成减少了神经模型大小或改善了语音速度。
