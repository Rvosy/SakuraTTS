# 将参考绑定接入日文运行入口

日期：2026-09-20。独立 Harness 已证明，五项参考投影可以替代 14 个常驻权重。本轮将它接入自有声学加载器和日文 CLI，并重新测量原始日文的完整请求。

## 采用方式

`MLXSoVITS.load(..., reference=reference)` 在一次模型包校验中先读取条件权重，按原 FP32 运算生成投影，再读取剩余权重。参考身份保存为独立 JSON 字符串，`ge/ge512` 保存为不可写的字节快照。声学接口在消耗噪声 RNG 前检查参考，直接 `decode` 也检查两个条件；更换参考需新建模型实例。

默认 `reference=None` 保留完整权重路径，CLI 的 `--bind-reference` 默认关闭。WeightNorm 折叠和 CPU FP64 softmax 累积继续独立选择。模型包、精度、文本及生成规则没有变化，因此本轮不涉及安装体积缩减。

## 先处理加载缓存

首轮产品实测发现，只去掉常驻权重还不够。完整路径在声学入口的 active/cache 为 173,176,320 / 0 bytes，绑定路径为 145,921,664 / 75,497,472 bytes。活跃内存少了 25.992 MiB，但投影准备的约 72 MiB 临时内存留在分配器缓存中，不能据此说加载后的总占用下降。

因此模型加载器仍只管理自己的权重和投影，由 CLI 在绑定加载完成并同步后清理空闲缓存。该操作不清除仍被模型持有的张量；耗时计入模型加载。Python 宿主继续自行决定是否清理全局分配器缓存。

首轮的四例原文对照完成 112 次成功请求、8 次预期失败和恢复；4 个普通 CLI 进程也成功，两个 seed 的完整 / 绑定 WAV 相同。首轮证据原样保留在 `SakuraTTS-References/runs/20260919T170055.114417Z-bound-runtime-suite/`，不以之后的缓存策略覆盖。

## 验证口径

完整请求沿用 `native_staged_lifecycle.py`，两组都先卸载 GPT，再加载 SoVITS。原始日文、实际语言前端、参考包、官方采样 draw 和声学 noise 相同；每次请求重新加载和卸载模型。正常计时包含文本前端、模型校验与加载、生成、输出复制、PCM 及卸载，排除初始导入、前置资源校验、金标读取和文件写入。

诊断和正常运行使用不同进程。诊断在整个请求之前重置 MLX allocator peak；边界 RSS 只作为快照，进程 lifetime maxrss 不解释为请求峰值。正常运行不做资源采样或峰值重置，每例中位数来自两轮共六次正式测量，首次和预热另存。

固定条件比较与独立随机 CLI 分开。CLI 使用 NumPy seed 0 / 1，只比较实际保存的文本、生成摘要和 WAV；JSON 没有完整 token 序列，因此不把 CLI 的摘要相同称为 token 序列已比过。新结果没有新增人工试听或 ASR。

## 完整请求结果

加入调用方缓存清理后，重新运行两组诊断和两组正常进程。112 次成功请求及 8 次预期失败后的恢复全部通过；原文、规范化文本、音素、拼接特征、生成 token、停止原因、语义切片及波形保持。四例 WAV 与此前基线逐字节相同。

下表的峰值是每例四次成功诊断中的最大请求分配器峰值，包含两模型的校验、加载和卸载。耗时是另外的正常运行中位数，两列不能来自同一次诊断计时。

| 原始日文样例 | 完整权重峰值 MiB | 绑定峰值 MiB | 完整权重耗时 s | 绑定耗时 s |
| --- | ---: | ---: | ---: | ---: |
| 报告句 | 541.959 | 515.967 | 1.490410 | 1.481005 |
| 短句 | 416.397 | 416.397 | 0.775250 | 0.767281 |
| 长句 | 1321.319 | 1295.327 | 3.603824 | 3.600175 |
| 标点句 | 822.225 | 796.233 | 2.173823 | 2.159773 |

三例整请求峰值少 27,254,656 bytes，即 25.992 MiB；短句最高点在 GPT 阶段，没有下降。声学入口的 active 从 173,176,320 降至 145,921,664 bytes，两组 cache 均为零。产品路径的差值比独立 Harness 的 26.023 MiB 略小，使用各自实测值，不混填。

四例正常请求本轮少 3.65–14.05 ms，幅度约 0.1%–1.0%。这是两组独立进程的批次中位数，没有据此承诺稳定加速。绑定 RTF 依次为 0.3085、0.8340、0.2413、0.2559，分母为不含末尾静音的音频主体。两组声学模型加载中位数均在约 154–157 ms，没有观察到明显加载回退。

每次请求卸载后，模型弱引用失效、MLX active/cache 均为零。诊断进程 lifetime maxrss 分别为 924,876,800 / 926,695,424 bytes，RSS 峰值没有改善。它包含 Harness、金标和 CPU 结果，也不能与 MLX 指标相加当作总物理内存。以上数据属于 Apple 统一内存，NVIDIA 独立显存仍待实机验证。

最后再运行 4 个真实 CLI 进程，完整 / 绑定各覆盖 seed 0 和 1，退出码均为 0；每个 seed 的 WAV 与文本、生成摘要相同。没有导入 Torch、Transformers 或中文前端。

本轮保留 `--bind-reference` 为显式选项：它已有可重复的分配器资源收益，但需要固定参考，换参考要重新加载；进程 RSS 和安装体积没有因此减少，CUDA 的收益也尚未证明。

## 逐层与生命周期补验

`sovits_bound_reference_validation.py` 另外用独立诊断进程覆盖默认、WeightNorm 折叠、FP64 softmax 累积及两者组合。默认配置对四例执行 A→B→A；折叠配置覆盖短句和标点句，两种 FP64 配置只覆盖标点句。B 保留 A 的 semantic、phones、noise，仅切换真实 B 的 `ge/ge512`，所以是声学探针。

40 组捕获包含 16 组同配置完整权重基线及 24 组绑定结果。绑定的 312 个阶段 / PCM 数组全部逐字节相同；默认完整路径的 8 组也与历史基线一致。观察真实 `read_fp32` 调用确认，每次加载 650 个权重各读一次，绑定先读 14 个准备权重，再读其余 636 个；常驻组件不保留前 14 个权重。

36 次错配在编码器执行前拒绝，之后的同实例正确请求恢复；24 次声学前 / 后取消均无 PCM 返回，同实例重试保持结果。另在 Decoder 已实际分配、完整模型尚未发布时注入 4 次加载失败，空 slot、组件弱引用失效，随后 4 次显式重载恢复。加载后再修改原始参考的身份及数组，绑定快照也没有变化。

默认与折叠配置仍保留原标点 MRTE 超差；两种 FP64 配置仅在本轮所测标点声学阶段通过原容差。没有扩大精度或模型覆盖范围，也没有修复原采样概率超差。该 Harness 使用固定语义和显式声学噪声，不新增 GPT、独立随机生成或试听结论。
