# 合作式取消与同模型恢复

日期：2026-09-19。公开 Python 生成接口新增可选 `cancel_requested` 谓词。返回真时抛出 `SynthesisCancelled`，异常的 `stage` 说明在哪个检查点取消，不返回成功结果或部分 PCM。

检查点为 Prefill 前后、每步采样后、Decode 返回后、声学执行前后。采样后即使本步达到 EOS，已请求的取消也优先于返回成功。模型或谓词自身抛出的原异常继续传播，不伪装成取消。

分阶段结果不持有谓词或回调，避免闭包间接保留模型。分阶段调用方须向两个接口显式传入取消来源；组合入口自动透传。`release_gpt_state=True` 的语义 `finally` 覆盖取消，权重的保留和卸载仍归调用方。默认 `None` 保留既有生成规则与随机数消耗顺序。

这只是计算边界上的合作式取消。当前模型方法返回前已求值，取消后才释放相应状态；没有中断运行中的 GPU kernel。CLI、宿主播放队列与跨进程取消协议尚未接入。

## 真实模型验证

`research/tools/native_cancellation.py` 在同一 worker 中加载两轮模型，每轮保持一对 GPT / SoVITS 实例。先运行四条原始日文，再针对原始短句依次触发四种取消，每次取消后紧接同一短句恢复请求：

| 取消位置 | 实际执行与拒绝结果 |
|---|---|
| Prefill 前 | 未调用 Prefill、采样或声学，直接取消 |
| Prefill 后 | 完成一次真实 Prefill，未调用采样或声学 |
| 第三次 Decode 后 | 完成三次真实 Decode，token 前缀与官方相同，后续生成停止 |
| 声学返回后 | 完整声学计算已完成，丢弃波形，未调用 PCM 转换 |

诊断子类只计数、保存标量状态和在真实方法返回后设置 Event，不修改输入或计算结果。PCM 包装器只计数并透传调用，用来验证取消后没有进入输出转换。取消异常只保存类型、文本、stage 和 traceback 字符串。

两轮共 16 次成功请求、8 次取消，实际 worker 与父进程退出码均为 0。八次取消均无返回结果、无 PCM 转换，也没有写出取消请求的音频。每次取消的 GPT 请求状态都清空；下一条使用同一模型对象恢复，四例 token、history、停止、semantic、目标 / 拼接特征、波形与 PCM 检查通过。波形通过官方容差，九组保存数组与自有基线逐位相同，四份 WAV 整文件相同。

每次取消后清理空闲缓存，MLX active 回到仅含常驻权重的 469.05 MiB，cache 为 0。两轮模型完整卸载后 active / cache 均为 0，弱引用确认模型对象已销毁；RSS 仍约为 889.89、860.66 MiB，不能把分配器清零当成进程内存归零。

Prefill 前取消没有新增 MLX 分配，重置后的原始 peak 计数为 0，但 active 仍为 469.05 MiB；这个计数不能解释为请求没有占用内存。报告保留两者，不使用取消尝试的该数值比较资源收益。

上述计时包含同步、状态捕获与边界采样。Event 在明确位置设置，这验证检查点和恢复语义，不是异步请求到达后的取消延迟，更不是硬实时或 Windows 显存验收。
