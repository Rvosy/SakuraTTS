# MaiBot N.A.V.I. 音色部署

日期：2026-10-26。本次修正 [首次部署](maibot-deployment-20261026.md) 使用夜乃桜基准音色的问题，并将手动命令改为 `/tts 日语台词`。插件版本为 0.2.1，旧命令 `/sakura_tts` 不再注册。

## 部署与验证

模型位于 `/opt/sakuratts/shared/models/navi-cpu-20261026/`，参考音频位于 `/opt/sakuratts/shared/references/navi-neutral.ogg`。正式 `service.yaml` 与插件 `config.toml` 同时切换，保留 `minimum-memory`、空闲 60 秒休眠及原有资源限制。引擎程序和 MaiBot 镜像未升级。

- 插件局部测试：20 项测试及 13 项子测试通过，覆盖 `/tts` 路由、多行文本与旧命令拒绝。
- CPU 模型资源检查通过；隔离服务的冷启动、连续请求和休眠后再次唤醒均返回 HTTP 200 / completed，短句合成耗时分别为 10.43、7.14、8.87 秒。结果只代表本次部署检查。
- 正式 MaiBot 已加载 `/tts`，组件启用、权限为 public。切换重启了 TTS 服务和 MaiBot 核心容器。

首次正式检查只覆盖纯日语短句，未发现日英混合资源缺失。随后实际聊天中 `/tts こんにちは。` 成功，而 Replyer 生成的 `Naviです` 触发 `Language segment G2P is not implemented: ['en']`，返回 HTTP 400。改为纯日语台词的聊天请求成功，确认问题位于文本前端。

已离线导出英文词典、词性模型和发音预测权重，部署为模型内的 `frontend-ja-en/`，并在引擎独立环境补装项目声明的 `nltk==3.9.2`、`wordsegment==1.3.1`、`inflect==7.5.0`。本地和 Linux 各通过 11 条导出一致性样例，Linux 依赖检查通过。用正式插件回放含 `Navi` 的原始失败台词，冷启动、连续合成和休眠后再次唤醒均返回 HTTP 200 / completed，分别耗时 19.82、14.77、18.27 秒，生成约 7 秒音频。部署检查脚本的默认输入改为日英混合，安装文档补充了资源要求。

修复后核对实际聊天历史：22:28:39 请求日英混合语音，22:29:17 已记录中文回复与包含 `Navi` 的语音台词，没有附加 HTTP 400 失败提示。音质仍需人工试听。测试命令：`/tts こんにちは。`。普通角色回复通过 Replyer 的语音扩展使用同一音色。

最终配置核对通过，人物卡、Host 配置、QQ 适配器容器与 console / telemetry 服务未改变。

## 群聊命令识别修正

同日升级插件至 0.2.2。实际群消息在 `/tts` 前包含 `@N.A.V.I.`，原先以 `^/tts` 匹配的命令未命中，入库标记为 `is_command=0`，随后进入普通 Replyer 流程，导致朗读内容被改写。修正命令正则，允许前置一个 @ 名称及空白，命令名不区分大小写；正文仍直接传给引擎。

21 项插件测试及 17 项子测试通过，包含群消息原句、大小写、多行文本和非命令句子不匹配。线上组件查询确认新正则已加载。切换前插件备份在 `/opt/maibot-snowluma/backups/tts-command-20261026/`，部署与原始命令回放证据在 `/opt/sakuratts-tts-command-20261026/`。

在 MaiBot 镜像内使用实际 Host 命令匹配器回放该群消息，调用已部署插件及正式引擎；断言 HTTP 请求文本与命令原文完全一致，生成 627244 字节 WAV。SDK 发送边界由测试接收，未向群里重复发消息。

## 固定 0.9 倍速

同日升级插件至 0.2.3，在 `config.toml` 的 `[voice]` 中设置 `speed_factor = 0.9`，手动命令与回复扩展共用。引擎切换至 `/opt/sakuratts/releases/20261026-fixed-speed/`，新增 HTTP 非流式输出调速；算法、范围和限制见 [API 字段说明](../../docs/api-v2-guide.md#音频与流式)。服务器安装 Ubuntu 仓库提供的 FFmpeg 6.1.1。

新引擎版本复用 `/opt/sakuratts/releases/20261026-integration/.venv-linux-cpu/`，因此原版本目录须保留。模型、参考音频与 CPU 档位不变。切换前插件和引擎链接目标保存在 `/opt/maibot-snowluma/backups/tts-speed-20261026/`。

HTTP、managed 生命周期与插件局部测试共 54 项及 63 项子测试通过，真实 FFmpeg 测试覆盖音高、时长、原速 PCM 不变及依赖缺失时不唤醒。服务器使用同一句话、同一个 seed 对比：原速 5.14 秒，0.9 倍速 5.674 秒；慢速 PCM 与对原速 PCM 直接执行同一调速处理的结果完全一致。此测量只证明调速路径，听感仍需试听。

本地证据位于 `outputs/tts-speed-20261026/`，服务器候选、部署脚本与对比音频位于 `/opt/sakuratts-speed-20261026/`。

正式部署后分别通过手动命令处理器与回复扩展调用引擎，两次请求及响应均确认倍率为 0.9，返回 HTTP 200 / completed；验证未向聊天平台发送消息。

## 手动朗读上下文

同日升级插件至 0.2.4。此前 `/tts` 指令按命令拦截，发出的语音又只记录为占位符，Maisaka 无法从当前上下文识别朗读内容。改为通过 `send.hybrid` 发送一个语音段，将请求者和原文保存在语音内容中，并注明台词由请求者提供。Host 使用原有发送链路，在发送成功后保存并同步会话历史；消息 ID 沿用平台回执，不额外发送文字或触发一次回复。

23 项插件测试及 21 项子测试通过。使用线上 MaiBot 镜像在断网隔离容器验证真实 SDK、发送服务和历史转换：成功时同步一条带原文的记录；失败时不保存或同步；数据库记录序列化后恢复仍保留原文；平台消息只包含音频。合成和平台投递使用替身，未向 QQ 发送消息，也未写入线上聊天数据库。实际群聊追问效果仍需测试，新记录规则不追溯补写旧语音。

线上确认 0.2.4 已加载，`/tts` 启用，配置逐字节保持不变，语速仍为 0.9。仅重启 MaiBot 核心容器。旧插件保存在 `/opt/maibot-snowluma/backups/tts-history-20261026/`，隔离验证和部署证据在 `/opt/sakuratts-history-20261026/`，本地副本在 `outputs/tts-history-20261026/`。

## 旧朗读请求的记忆整理

按请求对本次群聊测试中 22:40 至 23:33 的 61 条旧 `/tts` 请求执行一次记忆导入整理。保留请求者、原文及原始消息 ID，将台词标记为受托朗读引文；50 条可按处理顺序对应紧邻的语音记录，5 条有失败或忙碌提示，6 条无法唯一确认送达。未回写原聊天记录，也未把无法确认的请求改成成功状态。

通过现有 WebUI 记忆导入接口提交到该群的 `chat` 作用域，任务 `f48c41738b6e4f129889ac440a43e0e8` 的 4 个分块全部完成。核对四条有效记忆的作用域后，使用该群的记忆查询接口检索到全部四条。来源为 `web_import:tts-reading-history-20261026.txt`，服务器证据在 `/opt/sakuratts-memory-20261026/`；原始聊天快照保留在受限目录，不进入插件包。

## 旧语音记忆的内容修正

10 月 27 日完成修正。首次导入过多记录请求者、发送状态和消息 ID，派生摘要因此偏向语音测试过程。将同一批 61 条请求整理为四段内容：亲昵、问候与安慰；作品名、品牌名与戏剧化台词；谐音、骂人和成人玩笑；AI 支持中小企业的长文。正文保留原文及主要含义，重复台词去重，仍注明引文性质和部分请求无法确认播出。

修正接口写入四段新正文后，在收尾时返回 `database is locked`；核对实际落库结果，未重复导入。随后通过来源删除接口将旧四段及其 30 条派生关系移入回收区，操作 ID 为 `del_748b8ef6776d410899c17bc39ee3ea9a`。旧来源的 Episode 重建结果为零。

索引维护接口完成 395 条段落和 151 个实体的向量重建，无失败项。检查发现新正文在全局检索中可见，但以 `memory:<chat_id>` 为来源时未被本群检索召回。备份四条完整记录后，仅将其来源调整为该群现有的 `chat_summary:<chat_id>`，补充 `scope_type=chat`，再通过接口重建受影响来源的 Episode。本次未修改记忆内核代码，通用修正接口的锁冲突和来源范围识别问题仍需单独修复。

最终核对四段正文与准备文本一致；以本群为范围，分别询问“痛痛飞走”、领域展开等玩梗台词和中小企业长文，均返回对应正文，排名为第 2 条，首条为关联 Episode。旧来源没有有效 Episode。验证未向群内发送消息，实际对话如何组织回答仍需群聊验收。脚本、变更前记录、接口结果与断言证据在 `/opt/sakuratts-memory-content-20261026/`，本地副本在 `outputs/tts-memory-content-20261026/`。
