# CPU 三档、声码器块长与 KV 分配测量

本轮在[上一轮 CPU 内存优化](cpu-memory-20261026.md)基础上，将分块和两层错峰纳入正式档位，并调查分块后暴露的 GPT 峰值。产品默认值由 [profiles.py](../../sakuratts/profiles.py) 定义，不按云厂商、服务器内存或测试机器设置线程和容量。

## 档位与兼容

| 档位 | GPT / 声学 | 请求结束后的保留方式 | 分块包执行方式 |
| --- | --- | --- | --- |
| `balanced`，均衡，默认 | INT8 / FP32 | 模型和 KV 保留 | 完整声码器一次执行 |
| `low-memory`，省内存 | INT8 / FP32 | 语义结束释放 KV，模型保留 | 256 帧，latent / vocoder 常驻 |
| `minimum-memory`，极限省内存 | INT8 / FP32 | GPT / 声学错峰，每片结束卸载 | 128 帧，latent / vocoder 也错峰 |

三档保留相同采样规则、默认容量 2048 和输出格式。旧名 `int8`、`compact` 分别映射到 `balanced`、`low-memory`，显式执行参数仍优先。旧整图包继续使用原有 KV 释放或外层错峰行为；分块包才启用内部错峰和分块。显式整数块长配整图包会报错。实际选择写入合成报告和 `doctor`，不会把整图执行报告为分块。

使用原始权重时，两个省内存档共用 FP32 分块准备缓存，GPT 缓存不因档位而重复生成。普通加载不转换已有模型。配置、离线准备和 HTTP `managed` 要求集中在 [CPU 指南](../../docs/cpu-amd.md#cpu-省内存档位)。

## 对照条件与证据

- 模型为 Sakura V2ProPlus，GPT INT8、声学 FP32。复用上一轮的模型、前端与中性参考；固定日文短、长文本、seed 1234、`cut0`、GPT / 声学各 2 线程、容量 2048。没有修改采样参数、生成长度或精度。本机配置载入五份参考，Linux 配置载入一份；实际合成都使用内容相同的中性条件，各端前后不变。
- 本机为 Windows、Ryzen 7 9700X，复用整合包 Python 3.11.15、NumPy 2.4.6、ORT 1.30.0。Linux 复用已有 Python 3.12.3、NumPy 2.4.6、ORT 1.30.0 环境；2 vCPU，约 3.54 GiB 内存。全程没有在线安装。
- 每轮新进程。模型加载与首次请求分别计时；错峰档的模型加载包含在请求内。内存轮首次短句、热短句、长句各一次，本机每 50 ms、Linux 每 100 ms 采样；正式计时轮不启用采样线程或阶段钩子，包含首次短句、3 次热短句、2 次长句。空闲 RSS 取释放音频后 2 秒。计时不包括 WAV 写盘，不清空文件缓存。
- `outputs/cpu-profiles-20261026/baseline-source` 是本轮开始时的实现，已含上一轮分块能力和 ORT memory pattern 调整。服务器 `baseline/` 使用同一份源码。`candidate/` 为三档与 mask 优化版本，仍用 NumPy KV；`mapped/` 与本机 `mapped-source/` 为最终匿名映射版本。三份源码均有哈希清单，最终运行源码共 118 个 Python 文件。
- 原始结果、每次合成报告、PCM、资源采样、源码快照和日志保存在 `outputs/cpu-profiles-20261026/`，服务器回收记录在其 `server/` 子目录。`summarize.py` 重建 `summary.json` 与 `pcm-comparisons.json`。本轮基线与十月早期脚本的加载顺序、内存状态不同，不能把早期约 1.53 GiB 的数值直接作为本轮代码收益基线。

通用测量入口为 [cpu_memory.py](../tools/cpu_memory.py)，KV 研究入口为 [cpu_kv_experiment.py](../tools/cpu_kv_experiment.py)。前者分别运行 `--mode memory` 与 `--mode timing`；后者额外接受 `--kv-layout contiguous|layers|mmap`。两者可通过 `--source` 指定冻结源码。资源限制和 SSH 地址只在此次测试脚本中。

## GPT 峰值定位

运行时仍只有一个 CPU GPT Session，Prefill 与 Decode 共用图，没有再次载入原始 FP32 Transformer 权重。权重、声学工作区和前端常驻的初轮归因见[上一轮记录](cpu-memory-20261026.md#占用来源)。本轮没有通过增加模型缓存或关闭前端功能换取收益。

固定模型的两个 KV 数组合计 192.1 MiB 虚拟容量。短句 Prefill 为 247 个 token，结束时 343；本机长句 Prefill 为 484，结束时 1033。不能把尚未写入的虚拟空间全部当成 RSS。增长试验保留 2048 上限，以 256 行为增量，短、长句分别申请约 48.1 / 120.1 MiB 容量。

| 本机 KV 试验，模型常驻、256 帧声码器 | 完整请求峰值 RSS | 热短句中位数 | 长句中位数 |
| --- | ---: | ---: | ---: |
| 固定 NumPy 缓冲区 | 743.8 MiB | 1.64 s | 10.16 s |
| 连续缓冲区按需扩容 | 782.4 MiB | 1.61 s | 10.30 s |
| 每层分别按需扩容 | 742.6 MiB | 1.52 s | 9.98 s |
| 固定容量匿名映射 | 742.8 MiB | 1.54 s | 9.98 s |

连续扩容在复制时保留新旧内存，完整峰值反而增加；逐层扩容没有带来本机 RSS 收益。匿名映射保留连续地址和全部支持长度，避免扩容复制，由操作系统按页分配物理内存。Windows 没有测到同等内存下降，不能把这个改动描述成跨平台固定收益。

Linux 使用 `madvise` 大页策略。原 NumPy KV 的两个约 96 MiB 映射中，采样观察到合计 134 MiB `AnonHugePages`；未写满的层间预留区也可能随大页进入 RSS。NumPy 在 Linux 的大页提示机制见[官方说明](https://numpy.org/doc/2.4/reference/global_state.html)。实现只替换 CPU KV 的底层存储，不设置全局 `NUMPY_MADVISE_HUGEPAGE`，不修改系统大页策略或其他数组。DirectML 的 KV 分配保持原路径。

实际长句 Prefill 的逐节点统计中，`new_keys` / `new_values` 的输出拼接各约 22.69 MiB，注意力矩阵每层约 14.33 MiB；节点寿命不同，不能相加为峰值。修改这些图输出或注意力计算需要重新导出、评估融合和量化顺序，本轮未直接替换已有模型图。

Prefill mask 改为一次分配最终数组并就地填零，移除布尔矩阵、`where` 和 sentinel 拼接产生的副本。隔离测量中，长度 2048 的构造峰值由约 36.05 降至 16.01 MiB，耗时由 8.48 降至 1.91 ms，数组哈希一致；实际 484 token 的 mask 峰值由约 2.02 降至 0.90 MiB。这是局部数组分配统计，不是完整进程 RSS 降幅。

推理失败时还会清空 ORT 输入视图。调用方保留异常及 traceback 后，KV 数组和底层映射仍可释放；正常请求的驻留时机继续由三档策略决定，不新增强制 GC。

## 本机正式结果

RSS 为独立内存轮的操作系统高水位，时间为无采样轮的完整请求中位数。基线两个计时轮，其余最终版本各一轮；这些样本不能估计稳定 p95。

| 路径 | 峰值 RSS | 长句后空闲 RSS | 热短句 | 长句 |
| --- | ---: | ---: | ---: | ---: |
| 本轮基线 resident | 1121.7 MiB | 735.5 MiB | 1.49–1.59 s | 9.43–9.69 s |
| 最终均衡 | 1120.4 MiB | 734.4 MiB | 1.49 s | 9.08 s |
| 最终省内存，256 帧 | 742.7 MiB | 636.8 MiB | 1.55 s | 9.98 s |
| 最终极限省内存，128 帧 | 483.1 MiB | 289.5 MiB | 2.81 s | 11.69 s |
| 最终极限省内存，64 帧覆盖 | 482.4 MiB | 289.3 MiB | 2.81 s | 12.47 s |

本机均衡档没有可确认的实质内存下降；省内存档峰值约降 34%，长句较基线中位数范围慢约 3%–6%；极限档峰值约降 57%，短句受逐片加载影响明显。最终均衡档一次较快的计时不视为稳定加速。

最终均衡 / 省内存的模型加载分别为 1.26 / 1.11 秒，首次短句为 1.71 / 1.74 秒；极限 128 帧首次短句 2.96 秒，已包含加载。引擎初始化约 0.28–0.29 秒。内存轮均衡档的初始化、GPT 加载、声学加载边界约为 80 / 182 / 227 MiB，首次请求后空闲约 605 MiB，长句后约 734 MiB。模型页按访问进入 RSS，加载边界差值不等于模型全部工作集。

## 声码器块长

下表在相同两层错峰、原固定 KV 条件下比较块长，之后再用最终 KV 实现复测 128 / 64。

| 本机块长 | 完整峰值 RSS | 声学采样峰值 | 热短句 | 长句 |
| --- | ---: | ---: | ---: | ---: |
| 256 | 523.7 MiB | 523.7 MiB | 2.66 s | 11.24 s |
| 128 | 484.6 MiB | 478.9 MiB | 2.81 s | 11.87 s |
| 64 | 485.4 MiB | 457.5 MiB | 3.25 s | 13.11 s |

128 帧降低了声码器峰值，继续缩至 64 帧后，完整峰值由 GPT 决定。最终匿名映射复测仍呈现相同关系：128 / 64 帧的 GPT 采样峰值约 483 / 482 MiB，声学约 480 / 456 MiB。64 帧减少局部工作区，却没有继续降低本机完整峰值，长句约慢 6.6%。

## Linux 复测

测试目录为 `/opt/sakuratts-cpu-profiles-20261026`，保留旧轮目录和记录。每次测量使用独立 transient systemd service，沿用 `MemoryMax=2200M`、`MemorySwapMax=512M`、`CPUQuota=150%`、`Nice=10`，另设 1200 秒运行上限和 15 秒停止超时。执行时配置保存在每轮 `*.active-unit.txt`，进程内读取的 cgroup 数据保存在 `result.json`。服务回收后的 systemd 默认属性不用于解释实际限制。

| 路径 | RSS 高水位 | 长句后空闲 RSS | cgroup memory.peak | cgroup swap.peak |
| --- | ---: | ---: | ---: | ---: |
| 本轮基线 resident | 1320.5 MiB | 862.0 MiB | 1444.6 MiB | 5.0 MiB |
| 最终均衡 | 1279.1 MiB | 830.5 MiB | 1263.6 MiB | 0 |
| 最终省内存，256 帧 | 1147.0 MiB | 720.4 MiB | 1377.5 MiB | 0 |
| 最终极限省内存，128 帧 | 596.2 MiB | 433.4 MiB | 754.4 MiB | 0 |
| 最终极限省内存，64 帧覆盖 | 581.4 MiB | 452.1 MiB | 536.3 MiB | 0 |

上表均为独立内存轮。均衡、省内存、极限 128 帧的 RSS 高水位较基线分别低约 3%、13%、55%。RSS 与 cgroup 不相加：共享文件页可能由先前访问它的 cgroup 记账，cgroup 也包含 RSS 之外的文件缓存与内核开销。省内存档的 RSS 下降没有对应同等 cgroup 下降；64 帧的 cgroup 差值也不能当作块长的净收益。

100 ms 采样可能漏掉 GPT 瞬时峰值。128 帧极限档的 GPT 采样峰值约 560 MiB，但语义结束时内核高水位已达到 596 MiB，后续声学没有再推高。64 帧内存轮低约 15 MiB，空闲却高约 19 MiB；连续长句计时轮的高水位回到约 601 MiB，与 128 帧基本一致。本机 64 帧长句约慢 6.6%，完整峰值未下降。综合这些结果，默认选择 256 / 128 帧，64 帧保留为显式覆盖，不按单次较低的采样点决定默认值。

旧 NumPy KV 的省内存档高水位为 1257.3 MiB，最终匿名映射为 1147.0 MiB；逐层增长试验的内存轮 / 连续长句轮分别为 1064.6 / 1161.2 MiB，未显示优于最终匿名映射连续长句轮 1143.2 MiB 的稳定优势。原布局的大页采样峰值为 140 MiB，其中约 134 MiB 来自 KV；最终均衡 / 省内存的采样中只有约 4 / 6 MiB 匿名大页。Linux 的收益与大页策略、分配器和请求序列相关，不能外推为 Windows 的固定降幅。

## 验证范围与剩余问题

已验证真实小 ONNX 图的 FP32 / FP16 / INT8 推理、Prefill 双向文本与因果音频 mask、2048 容量边界、满缓存后短请求重置、失败 traceback 保留时回收存储；还覆盖 CPU 三档与别名、两种声学包、参数覆盖、准备缓存、诊断、声学分块和已有 DirectML 回归。最终相关测试共 88 项通过；GPU 部分使用既有替身与图测试，没有重新执行物理显卡基准。

共比较 271 份 WAV 的解码后 PCM。本机 151 份全部逐样本一致；Linux 120 份中，整图路径和所有短句一致，27 份分块长句各有 13 / 688000 个样本相差 1 LSB，约占 0.0019%，最大误差为 16-bit PCM 的一个量化单位。所有输出的音素、采样 token、语义 token、停止原因、样本数和采样率均与同机基线一致。短句均为 4.14 秒；本机长句为 22.26 秒，Linux 为 21.50 秒。跨平台 INT8 输出差异不记为本轮改动收益或退化。

27 个临时服务均退出 0，分别保存了运行中资源限制；最终没有残留同名前缀的 systemd unit。`sakura-console.service`、`sakura-telemetry.service` 前后均 active，PID 保持 874 / 875，没有修改常驻业务。服务器最终源码的 118 个文件与本机冻结版本一致，15 份模型、参考、前端与分块资源哈希核对通过。汇总见 `final-metrics.json`、`server/source-verification.json`、`server/input-verification.json` 和 `server/final-units.txt`。

完整合成范围限于 Sakura V2ProPlus、固定日文短长句和中性参考；尚未进行人工盲听、多模型、多语言、所有容量位置的真实大模型音质验收，也没有声称支持任意文本下相同峰值。2048 边界通过真实小图验证，正式长句没有填满容量。长时间服务、更多碎片化请求序列及同等背景负载下的请求延迟仍需另测。

前端字典、语言识别资源、模型权重、ORT 临时张量和系统分配器保留仍占内存。匿名映射不会消除这些成本；进一步压低 GPT 注意力峰值需要图级改动和新的数值、延迟验证。极限档的重载成本是显式选择，均衡档仍优先保持连续请求速度。
