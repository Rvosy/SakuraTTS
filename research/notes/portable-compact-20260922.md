# 完整整合包缩减与首次使用验收

日期：2026-09-22。环境：本机 Windows / RTX 5060。默认 direct 与 FP32 保持不变。

## 体积

上一轮完整包把 CUDA 版 PyTorch 带进了只在 CPU 上执行的准备环境。PyTorch 本身占 5.01 GB，准备环境还带了一份 641 MB 的 GPU 版 ORT。此次改用 CPU PyTorch / torchaudio，并只保留本地 ORT 的 CPU 核心；主推理仍用 CuPy 与独立 ORT CUDA 工作进程。

| 项目 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 准备组件清单内文件 | 7,039,804,531 字节 | 1,669,319,811 字节 |
| 完整包清单内文件 | 10,899,045,012 字节 | 5,512,342,617 字节 |

完整包不含用户发声模型、参考录音、生成音频或转换缓存。上述数值是解压后发行文件的逻辑大小，不是压缩大小，也不包括用户运行后生成的缓存。准备组件保留 HuBERT、说话人编码器和语言识别等公共分析资源。

CPU PyTorch 仍附带约 850 MB 的编译静态库，其中 `dnnl.lib` 约 697 MB；这些库与头文件、依赖测试目录一起排除。主解释器移除 GUI、安装工具和 NumPy 测试文件，保留 CuPy、NVIDIA、NumPy 运行时编译所需头文件。

最终完整压缩包为 **1,960,862,106 字节（1.961 GB，约 1.826 GiB）**，低于 2,000,000,000 字节目标，余量约 39.1 MB。文件位于本地 `dist/compact/release/SakuraTTS-Windows-NVIDIA.7z`，SHA256 为 `060220a7806a8be5b0deaa2d93aff32a9b6cbe650573d6ed336dd5e786a16a92`。

压缩采用 7z LZMA2 solid、`mx=9`、128 MiB 字典、2 个压缩线程，耗时 775.02 秒，`7z t` 校验通过，耗时 37.05 秒。251.66 MB 本地样本改成 256 MiB 字典并增加搜索长度后，仅小 0.056%，耗时增加约 22%，因此没有加新的压缩档位。

从最终压缩包重新解压耗时 50.84 秒。18,572 个发行文件的 SHA256 全部匹配，无清单外文件；74 个产品 Python 文件与源码一致。解压副本通过 NVRTC、FP32/FP16 GEMM、CUDA Graph 和 ORT CUDA 实际运算，主进程没有导入 PyTorch。汇总结果保存在本地 `dist/compact/release/verification-report.json`，压缩包与 SHA256 文件也在该目录。

CPU torch / torchaudio 在用户说明流量限制前已启动下载，停止请求返回时已经完成，下载工具报告约 207.5 MiB；随后没有再下载。组件构建、压缩和验收只读取本地文件，构建器本身不会联网补依赖。

## 实际运行

从空缓存开始，使用用户原版 GPT `.ckpt`、SoVITS `.pth` 及一份新参考录音，通过原版 HTTP 字段完成了：

- 自动准备日文前端、转换两份原始权重、编码参考音频并生成 WAV。
- 同进程重复请求、managed 重启、默认 direct 启动复用磁盘缓存。
- managed 休眠后推理进程及其子进程退出，控制服务保留；正常结束后整个测试进程树被回收。
- 包外工作目录及错误的外部 Python/CUDA 环境变量不影响启动，观察到的应用进程使用包内解释器。

本次完整验收耗时 67.09 秒。其中首次转换加唤醒约 26.09 秒，首次参考准备加语音请求约 23.88 秒，紧接着的重复请求约 0.281 秒，缓存重启唤醒约 4.47 秒。这是单机单次数据，且当时正在压缩，不能视为性能基准。

四份 WAV 均为 32 kHz、单声道、110,720 个 int16 采样点，时长 3.46 秒。重复、重启和 direct 相对首份音频分别有 16、13、20 个采样点不同，最大差均为 1 LSB。改用 CPU wheel 前后的首份音频也等长，20 个采样点相差 1 LSB；未达到逐字节一致，不把它表述为完全相同。

随后把整包移动到带空格的目录，确认原安装目录不存在。managed 与 direct 均复用已有模型、参考缓存；搬迁前后音频等长，最大差仍为 1 LSB。在新目录使用第二份未缓存的参考录音，也成功自动处理：模型缓存保持不变，只新增一份参考缓存；重复请求复用缓存，两份音频均为 3.26 秒，最大差 1 LSB。准备进程来自搬迁后的目录，CPU FP32 设置不变，休眠及服务退出正常。

裁剪后的准备解释器已实际导入 PyTorch、torchaudio、ORT、SciPy、librosa 和 pyopenjtalk，并执行 Numba JIT。PyTorch 为 `2.7.0+cpu`，`torch.version.cuda` 为 `None`，没有初始化 CUDA。

302 项完整回归通过；修正系统辅助进程识别后，10 项验收脚本测试通过。发行包的 74 个产品 Python 文件与当前源码逐字节一致，wheel SHA256 为 `334e98d109ba373943ea6d36e53bf335549911c6084946dec034776e1d06f495`。

首次实机验收曾因脚本把 Windows 的 `cmd /c ver` 当作包外依赖而失败。该轮产品已成功出声并休眠；报告保留，修正后另用空缓存重跑，没有改写旧报告。

## 链路精简

配置格式校验统一交给 `Model.load`。模型打包去掉复制前的完整校验，保留发布前一次；首次转换直接重命名组装产物，避免再复制整套模型后才发布。准备组件和完整包构建也去掉了一次重复的全目录哈希读取。

便携参考缓存使用准备组件清单作为内置辅助资源身份，避免再次遍历 HuBERT 和声纹模型；显式指定的外部 HuBERT 仍按内容区分。参考准备去掉了子进程重复预检、两轮输入全量哈希，以及刚保存数组后的立即读回。父进程仍记录输入身份并确认原文件没有被修改。

保留模型与参考身份、文件完整性、路径边界和原子发布；进程通信保留请求互斥、取消、背压、状态核对与退出回收。这些检查分别保护真实的文件或进程边界，没有为本次缩包增加通用校验框架。

后续仍可研究让声学子进程独占模型内容校验，减少父子进程重复读取；这次未改变声学初始化契约。

## 继续缩减与验证边界

准备环境的韩文词典、ipadic、wordfreq、jieba 系列合计约 288 MB。它们由原版的多语言导入链带入，继续缩减应先拆开非日文导入，再删除依赖。直接删目录会破坏原版 TTS 导入；这一轮保留它们。现有 GPU 库没有发现可以直接安全删除的大项。

尚未在第二台干净 Windows 或其他显卡上验收，也没有完成听音评估。本轮未重新测量峰值显存；休眠通过指推理进程树实际退出，不代表整机所有程序的显存为零。文件路径和进程记录不能代替操作系统级文件访问或网络隔离审计。公开分发前仍需补齐辅助权重的许可与来源声明。
