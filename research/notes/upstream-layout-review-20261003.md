# GPT-SoVITS 兼容目标与仓库结构复核

日期：2026-10-03。项目基线为 `bcf8755`，GPT-SoVITS 基线为 `48b1a0169a28582a8984402f82cf438d3bfa6aca`。上游本地副本与该提交一致，API 字段快照见 [gpt_sovits_api_v2.json](../../tests/fixtures/gpt_sovits_api_v2.json)。

## 前次架构判断的适用范围

“梳理项目架构冗余”的主要事实判断有依据：HTTP 的 Inference 同时负责配置、转换和模型切换；Python/CLI 与 HTTP 对原始权重和参考的使用流程不同；NumPy GPT 仍服务 ONNX 导出；CUDA 低显存、取消和进程回收具有实际消费者。`research/` 已排除在发行包之外，文件数量不能直接说明运行包臃肿。

将 Genie 的角色入口列为首要改造方向、把目录和函数归属放到最后，偏离了以 GPT-SoVITS 为主要参照进行仓库重构的要求。角色名和命名参考可以保留为便利入口，但不能取代上游权重、参考路径和请求字段的语义。Piper 的对象组织方式也只能作为辅助参考。

当前已经实现多种设备和日英推理，仍不足以得出“绝大多数上游功能已完成兼容”的结论。此前 Spec 和路线图明确排除旧版 API、Gradio 与原版 Python 接口，将既有交付子集写成最终范围，与完整兼容目标不符。完整目标和各维度缺口现由[兼容矩阵](../../docs/specs/compatibility-matrix.md)统一记录。

## 前次分析遗漏的约束

1. **明确比较对象。** 上游版本必须固定；模型家族、语言、原始权重和辅助资源、YAML、HTTP、Python、WebUI/Gradio 及训练工具联动分别核对。API V2 与 V2 模型家族不是同一概念。
2. **检查参数的整条调用链。** Schema 接受不代表后端已实现。例如 Top-p 的字段与采样函数存在，语义生成仍拒绝非 1 值；`parallel_infer=true` 在单项批次中可接受，不代表已有并行批量推理。README 的强制 `parallel_infer=false` 已过时。
3. **给出上游到本项目的代码映射。** 切分规则、语言分段、文本特征、语义生成、声学、资源准备与进程设施应能分别定位。只有通用的“配置/资源/会话”建议，不能回答函数具体归属的问题。
4. **覆盖文件迁移的完整闭包。** 除导入外，还要更新工作进程按路径启动、转换脚本定位、脚本哈希、源码快照、wheel/sdist 清单、整合包检查、测试夹具和文档链接。模型资源目录与代码目录不能一起重命名。
5. **区分兼容目标和本次验证。** 文件移动不改变模型支持范围；既有数值实现、默认值和生命周期应先保持，再分别实现缺失能力。独立运行环境、研究证据、第三方许可和失败原因需要保留。

## 结构调整

核心包移到根目录 `sakuratts/`，采用 `TTS_infer_pack`、`text`、`AR` 和 `module` 的上游职责划分。设备实现继续位于 `backends`，运行设施归入 `runtime`，转换与缓存归入 `prepare`。`engine.py` 保留公共 Engine 和 Audio；Inference、配置读取、转换缓存、语言分段及切分函数分别移到各自模块。

当前文件职责见[架构说明](../../docs/architecture.md)，旧路径映射见[开发指南](../../docs/development.md)，取舍见 [ADR 0007](../../docs/adr/0007-upstream-layout.md)。模型文件、已准备资源、HTTP 参数和旧公共入口保持原有用法。

## 回归结果

- 产品测试运行 379 项，1 项跳过，其余通过；新增固定上游切分样例，覆盖六种切分方法，并检查旧入口的延迟导入。
- CPU 与 DirectML 分别使用 N.A.V.I 预制模型、seed=1234、`cut5`，对照重构前后各一条短句和一条多片段请求。四组 PCM 均逐样本一致，按片回调拼接结果与完整输出一致。CPU 使用 ORT 1.30.0，DirectML 使用 ORT 1.24.4；这次未测性能或重新评定音质。
- wheel 与源码包构建及哈希校验通过，包含 108 个 Python 文件和 16 份许可证/归属文件；源码包解压后不依赖研究目录，379 项产品测试同样通过、1 项跳过。验收发现并补齐了 `packaging/auxiliary-model-sources.json` 的原有发布遗漏。
- 工作进程隔离、模型切换失败恢复、转换缓存、managed 睡醒及 HTTP 回归由产品测试覆盖。CUDA / MLX 实机、完整 Windows 7z 整合包及新参考的真实编码未在本次重验。

音频身份和样例结果见[回归证据](../experiments/data/2026-10-03-layout-regression.json)。

## 尚需推进

完整兼容的缺口按兼容矩阵逐项实现和验收。Python/CLI 的原始模型与新参考便利入口、配置在父子进程间的重复解释、准备组件对上游完整 TTS 导入的依赖仍有改进空间；本次没有引入角色管理器，也没有删除转换器和低显存路径仍使用的实现。

历史研究测试中，`test_acoustic_precision` 仍按旧限制期待筛查报告和执行选项拒绝，`test_package_sovits_chunks` 仍期待旧来源约束；同环境下，重构前后均为 151 项、2 个失败、6 个错误、2 个跳过。六个错误来自缺少 CUDA provider 时走到设备检查。它们与当前已放宽的资源加载契约不一致，不能通过恢复旧限制来让测试变绿，应在研究工具维护中单独处理。
