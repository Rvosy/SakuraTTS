# Windows 便携包 7z 压缩实验（2026-10-05）

## 输入和方法

输入为本地 `portable/` 的发行清单：18,575 个文件，共 5,512,352,446 字节，不包含用户模型、参考音频和运行缓存。压缩另包含 `bundle-manifest.json`。开始前逐文件核对 SHA256，仅缺失清单要求的空文件 `cache/.keep`；恢复该空文件后全部匹配。没有更改模型精度或删减依赖。

机器为 Windows、Ryzen 7 9700X、约 47.1 GiB 内存，使用本机 7-Zip 25.01 x64。实验期间有完整包压缩和其他本地工作并行，耗时是该次运行的墙钟时间，不能视为隔离条件下的速度排名。

采样取最大的 16 个文件，各读头、中、尾三个互不重叠的 8 MiB 片段，共 384 MiB。片段保持原扩展名。样本用于筛选搜索参数；它不能保留完整 DLL 结构，也不能重现大字典在完整文件和跨文件重复数据上的全部收益。日常打包脚本的快速采样仍取最大的 12 个文件，小文件只读取一次。

复跑五组 7z 样本实验：

```powershell
python research/tools/benchmark_portable_compression.py `
  --bundle portable --output tmp/7z-study-new
```

## 样本结果

所有 7z 组均使用 LZMA2、solid、2 个线程、`mx=9`；自动可执行文件过滤器保持默认。各组均通过 `7z t`、实际解压和样本 SHA256 校验。

| 设置 | 压缩字节 | 压缩秒 | 解压秒 |
| --- | ---: | ---: | ---: |
| 128 MiB，原排序 | 167,899,291 | 46.792 | 3.586 |
| 128 MiB，`qs=on` | 167,908,155 | 40.076 | 3.531 |
| 256 MiB，`qs=on`、`fb=273` | 167,679,680 | 50.282 | 3.528 |
| 512 MiB，`qs=on`、`fb=273` | 167,679,680 | 58.361 | 3.703 |
| 256 MiB，`qs=on`、`fb=273`、`mc=1000` | 167,663,547 | 97.997 | 3.501 |
| ZIP Deflate，`mx=9`、2 线程 | 215,735,528 | 53.290 | 未计时 |

ZIP 组使用同一份样本和文件清单，通过 ZIP CRC 和逐文件 SHA256 校验。128 MiB 7z 比 ZIP 小约 22.17%；256 MiB 加长匹配仅比 128 MiB 7z 小约 0.13%。进一步增加搜索深度只省 16,133 字节，耗时接近翻倍，没有加入发行档位。

## 完整包结果

对同一发行清单分别运行：

```powershell
python scripts/archive_portable.py --bundle portable `
  --output dist/7z-20261005-baseline --profile maximum
python scripts/archive_portable.py --bundle portable `
  --output dist/7z-20261005-extreme --profile extreme
```

| 档位 | 压缩字节 | 压缩秒 | `7z t` 秒 |
| --- | ---: | ---: | ---: |
| maximum | 1,960,849,296 | 839.138 | 37.678 |
| extreme | 1,899,321,527 | 1,171.319 | 35.066 |

`extreme` 比原参数少 61,527,769 字节，约 3.14%；产物约 1.899 GB（1.769 GiB），相当于发行文件原体积的 34.46%。完整包收益明显大于样本收益，但这两组同时改变了字典、匹配长度和排序，不能把全部收益归给某一个参数。

体积优先时选 `--profile extreme`。默认仍为 `maximum`，压缩时间和内存成本较低。512 MiB 字典解压也需要相应内存；尚未在低内存机器上测试。没有穷举参数，不把本次最小产物称为所有设置下的最小值。

压缩包分别保存在上述本地输出目录，均带 `.sha256` 和 `compression-report.json`。样本与完整包原始测量见 [JSON 记录](portable-7z-20261005.json)。

两份压缩包均完成实际解压：`maximum` 为 54.187 秒，`extreme` 为 48.447 秒。各包的 18,575 个发行文件逐一核对 SHA256 全部匹配，另核对清单文件与源清单逐字节一致，没有清单外文件。解压耗时不包含后续哈希读取；单次结果不足以判断哪个档位解压更快。各输出目录的 `verification-report.json` 保存校验结果。

归档相关 4 项测试通过，覆盖中文和空格路径、7z 往返、清单外文件排除、篡改拒绝、tar 权限保留及采样不重复；研究脚本另用独立小包跑通五组设置。此次验证针对无损归档，没有重跑 TTS 推理或干净机器验收。

## 参数依据

依据本机 7-Zip 25.01 的 `7-zip.chm`，`Command Line Version / Switches / -m`：

- LZMA2 在高压缩等级下用 1～2 个线程时不做多线程分块；增加线程可能失去跨块匹配。保留 2 个线程。
- solid 可复用文件之间的重复内容，但单独提取后部文件可能要先解码前面的数据。便携包通常整包解压，适合 solid。
- `qs=on` 按扩展名排序，有时能让不同目录中的相似文件更靠近。不能保证每个输入都变小；本次样本就略有增大。
- 大字典能匹配更远的重复内容。解压内存至少需要容纳字典，编码器还需要匹配查找结构；512 MiB 完整包压缩进程观察到约 5.7 GB 工作集，这不是精确峰值测量。
- `fb=273` 延长匹配搜索；更大的 `mc` 通常继续增加耗时，收益取决于数据。

本包有 141,637,345 字节的逐字节重复内容，分散在多个解释器环境。压缩可利用它们；直接删除文件则会改变运行时布局，本实验不做这种变更。

参数选取不等于全局最优。尚未穷举更大的字典、手工文件排序或所有过滤器组合。模型量化、替换 CUDA 依赖和删减功能属于另一个问题，需要单独验证行为与质量。
