# 后台资源精简与极限显存档接入

日期：2026-09-22。本轮继续完善可选 `managed` 模式，以显存为优先，同时减少控制服务的系统内存与退出后的资源残留。默认 `direct`、FP32 精度和原有请求参数保持不变。

## 主存与显存分开记录

[首轮报告](managed-runtime-20260922.md)的约 75 MB RSS、560 MB 私有提交都是系统内存指标，不是显存。RSS 表示当前驻留的物理内存；私有提交是系统为进程私有内存承担的提交量，两者不能相加。GPU Dedicated Usage 才是这里主要比较的显存指标；Shared GPU Usage 是 GPU 使用的共享系统内存用量，另行记录。

首版控制服务从生成模块导入取消异常时，也导入了 NumPy；IPC 在唤醒、音频拼接和关闭过程中同样依赖 NumPy。现在取消异常移到轻量模块，控制侧 PCM 使用标准库 `array`。推理进程继续使用原来的 NumPy、GPU 后端和采样代码，默认路径的音频转换没有变化。

相同本机启动方式、标准档合成后休眠的对比如下，均包含 Python 启动器及 HTTP 服务，单位为十进制 MB：

| 主存指标 | 首版 | 精简后 |
| --- | ---: | ---: |
| RSS 中位数 | 74.7 MB | 68.0 MB |
| 私有提交中位数 | 559.6 MB | 45.5 MB |

私有提交减少约 92%，不等于释放了同等数量的物理内存或显存。精简后标准档的 30 秒休眠观察包含 333 个样本，实际跨度 29.99 秒，CPU 时间没有可见增长。极限档的休眠 RSS 为 68.7 MB、私有提交为 46.4 MB，同样没有可见 CPU 时间增长。

## 休眠之外，降低合成期间的显存

既有 H 极限档现在可经 `managed` HTTP 使用。它在每个片段内依次加载 GPT、释放 GPT、执行声学模型、释放声学模型；不把这项取舍应用到默认模式。`direct` 仍拒绝总体 `policy="staged"`。

H 档唤醒后返回 `state="awake"`、`preparation="runtime_init"`，表示运行环境及前端已构造。GPU 权重尚未加载，`model_loaded` 始终为 `false`；所选模型仍可通过 `model` 查看。A / C / E 保留 `preparation="model_load"`，E 的声学 Session 仍按原策略在执行时创建。任何一种状态都不保证执行预热或未知参考条件已完成。

本轮使用 RTX 5060、Windows WDDM、现有 FP16 chunk256 模型与编译/参考缓存，固定短句、参考、seed=1234、cut0：

| GPU / 延迟指标 | managed 标准档 C | managed 极限档 H |
| --- | ---: | ---: |
| 本轮短句观测 Dedicated 峰值 | 689.0 MB | 395.9 MB |
| 合成后、尚未休眠的 Dedicated | 569.4 MB | 106.5 MB |
| 合成后、尚未休眠的 Shared | 165.7 MB | 86.0 MB |
| 完全休眠后 | 推理进程树退出，无对应 GPU 计数实例 | 推理进程树退出，无对应 GPU 计数实例 |
| 唤醒准备耗时 | 4.172 s | 1.328 s，仅运行环境准备 |
| 准备完成后的第一句，首 PCM | 1.078 s | 3.946 s |
| 随后两句，首 PCM | 0.239、0.234 s | 3.131、2.876 s |
| 休眠中直接提交合成，首 PCM | 4.976 s | 5.463 s |
| 热流式短句，首 PCM / 完整 | 0.259 / 0.284 s | 2.789 / 2.980 s |

两档各 5 次请求、direct 模式 3 次请求，共 13 次输出的 221440 字节 PCM 全部一致，SHA256 为 `365999ed967f98090b79cb3221d912a3eda4daa5edc1d71aca718f2af83509f5`。direct 对照也显式选择相同的 FP16 配置，这不是 FP32 与 FP16 的逐位对照。

采样请求间隔为 50 ms，实际包含进程树、句柄和 GPU 计数查询的耗时：标准档采样间隔中位数 90.7 ms、最大 227.8 ms，极限档中位数 91.6 ms、最大 235.7 ms。因此峰值只是本轮短句的观测值，可能漏过瞬时分配，不能取代既有混合长短句基准中的约 465.1 MB，也不能承诺任意文本低于 400 MB。短句延迟每种场景仅一到两个样本，不报告 p95 或稳定加速比例。

GPU 计数实例消失保留为 `null`，不填数值零。H 档在合成后仍有约 106 MB 的进程级 GPU 占用；完整休眠才退出这些进程。H 的较短唤醒时间也不是更快的首句，因为 GPU 加载工作移到了合成请求内。

## 反复睡醒与句柄回收

最初的真实模型压力测试发现：推理进程每轮都能退出，但控制服务的句柄呈阶梯增长，之后才随循环垃圾回收下降。排查确认，读管道线程将 EOF 异常直接放入队列，异常的 traceback 又引用线程栈帧和同一队列，形成循环引用。写管道异常有同样的问题。Popen 和进程树对象本身已经销毁。

现已在跨线程交付异常前移除 traceback、cause 和 context，保留异常类型及消息，消费者重新抛出时仍有本地调用栈。回归测试禁用循环垃圾回收，并强制终止消息已入队，确认休眠后传输线程对象立即释放。另一次不使用 GPU 的 100 轮对照中，禁用循环垃圾回收后句柄保持稳定。

最终完整回归为 271 项通过，耗时 34.78 秒。包括 22 项进程边界测试、18 项控制服务 HTTP 测试，以及 4 项 managed staged 加载测试。隔离导入测试禁止控制侧导入 NumPy、CuPy、Torch、ORT、推理后端和文本前端，并验证唤醒、完整音频、流式、取消及再次睡醒。

最终源码另完成标准档的 100 轮真实模型唤醒与休眠，耗时 397.17 秒。每轮都等待实际进程退出，确认没有残留推理子孙，且控制服务的进程树没有 GPU 计数实例。进程树总句柄始终在 368–369 之间；第 1 轮为 369，第 100 轮为 368。期间第 1 轮及每 10 轮合成一次，共 11 次短句、其中 5 次流式，PCM 全部与上面的固定哈希相同。服务最终正常退出，退出码为 0。

100 轮休眠采样的 RSS 范围为 67.2–72.3 MB，私有提交为 45.4–50.3 MB。第 1 / 100 轮分别为 RSS 67.7 / 71.0 MB、私有提交 46.2 / 48.9 MB。主存仍有小幅增长和波动，不能据此声称任意时长都恒定；本轮只确认没有此前的传输线程句柄积累。

上面的 13 次 GPU 音频与性能测量发生在句柄修复之前，其源码快照保存在 `result.json`。之后产品源码只修改了 IPC 异常清理；最终版本的睡醒压力测试单独记录源码哈希，保存在 `soak-result.json`。修复前的 59 轮诊断基线保留为 `soak-handle-growth-baseline.json`，该轮在定位问题后主动停止，不计为完成的 100 轮测试。

## 为什么本轮没有默认增加执行预热

首轮最后一次标准档日志中，第一句的参考准备约 195 ms、目标文本处理约 1 ms、GPT 约 287 ms、声学约 464 ms；热句的对应值约为 2 ms、1 ms、155–163 ms、40 ms。首次声学执行是主要的额外成本，参考阶段还包含首次语言检测模型加载，不能全部归因于读取参考音频。

假句预热会提前使用算力，可能增加唤醒后的缓存驻留；极限档又会在执行后关闭这些模型和 Session。当前没有足够证据证明额外预热能在既定显存约束下保留收益，因此本轮保留提前加载，不默认运行假句，也不增加 CPU 权重快照。后续可单独测量带参考文本的可选准备，再决定是否增加接口。

## 复现材料

本机记录位于忽略目录 `outputs/managed-refinement-20260922/`：`verify.py` 依次测量两档控制模式与默认模式；`result.json` 保存参数、PCM 哈希和产品源码哈希，`summary.json` 汇总三份 `*-samples.json`。日志与 WAV 在同一目录。使用已有模型与参考，不重新转换资源；这些本机资源不随 Git 分发。

```powershell
.venv\Scripts\python.exe outputs/managed-refinement-20260922/verify.py
C:\Python313\python.exe outputs/managed-refinement-20260922/summarize.py
```

测试中空闲超时设为 3 秒，产品默认仍为 60 秒。需要更快释放时可以显式缩短空闲窗口；提前唤醒的 `keep_alive_seconds` 也应相应设置，否则仍会保活到原截止时间。两项期限均到达后才自动休眠。

100 轮压力测试使用 `soak.py`，保持 60 秒空闲窗口，每轮完成后显式休眠。它与前述计时测量分别运行；压力测试开头与最终单元测试有重叠，不用其唤醒耗时推导性能结论。该轮不等于 100 轮长文本对话，也没有覆盖数小时挂机、其他机器、H 档 100 次睡醒、陌生参考峰值或无缓存首次部署。
