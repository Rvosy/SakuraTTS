# Genie 与 SakuraTTS：同机完整请求对比

本记录保留档位收敛前的测量与试听。现行 CPU / AMD 入口只保留 CPU `int8` 和 DirectML `fp16`，默认参数见[推理档位](../../docs/inference-profiles.md)。本轮 Sakura 的 CPU 与 AMD 均使用 ORT DirectML 1.24.4；CPU 安装包所用的 ORT 1.30.0 不沿用此处的性能数值。

同一台 Ryzen 7 7840HS / Radeon 780M，使用相同日文文本、N.A.V.I 中性参考音频。Genie 使用用户安装的 CPU 运行时及原始默认设置；Sakura 使用独立 CPU 或 AMD 配置。

## 方法与限制

原始结果位于 `results/genie-comparison-20260927/`，精简归档见[测量证据](../experiments/data/2026-09-27-genie-comparison.json)。配置依次启动新进程，先测冷短句，再按句长预热一次、热测三次。Genie 在所有 Sakura 配置之前、之后各跑一轮，合并每种句长的六个热请求；Sakura 每种配置、句长各三个。所有进程串行运行，计时包括文本前端到完整 PCM 返回，不包括 WAV 写盘。

Genie 使用 `C:/Users/LBW/AppData/Local/Sakura Development/tts/cpu/runtime/python.exe`，预转换音色来自 `sakura-v0.9.8-windows-x64/data/tts_bundles/onnx/N.A.V.I`。Sakura 的原检查点与参考身份已验证；Genie 预转换资源没有原检查点身份清单。Genie 保留图内随机采样、文本前处理和最多 500 轮解码的停止规则；Sakura 固定 seed=1234、top_k=15、temperature=1、repetition_penalty=1.35。它们不是同一计算图的等价输出。

下表为热请求中位数。RTF 是生成耗时除以生成波形时长，越低越快；这里去掉 Sakura 额外附加的 0.3 秒尾静音，未裁剪模型自己生成的停顿。Genie 没有对应的外加尾静音。RTF 仍不能证明读音、信息完整度或音质等价。

| 配置 | 短句耗时 s | 长句耗时 s | 长句波形 RTF | 峰值工作集 MiB | 峰值私有内存 MiB |
|---|---:|---:|---:|---:|---:|
| Genie 原版 CPU，前后两轮合并 | 1.489 | 14.540 | 0.750 | 5175.1 | 6706.2 |
| CPU FP32，8 线程 | 2.077 | 13.491 | 0.661 | 1350.7 | 1678.2 |
| CPU FP16，2 线程 | 4.351 | 31.372 | 1.553 | 1494.7 | 1996.2 |
| CPU INT8 GPT + FP32 声学，8 线程 | 1.521 | 10.855 | 0.544 | 1123.6 | 1451.6 |
| AMD FP16，容量 1280 | 1.272 | 8.278 | 0.406 | 1783.2 | 2427.7 |
| AMD FP16，容量 512，仅短句 | 1.001 | 未测，容量不足 | — | 1222.3 | 1833.2 |

表中的 CPU 线程数为声学线程，GPT 均为 4 线程。CPU FP16 的当前包仅准入已验证的 2 线程会话；FP32 / INT8 使用 8 线程。因此本表比较可用配置，不能把 CPU FP16 与其他行的差异全部归因于精度。8 线程 FP16 尝试在加载时被明确拒绝，未产生音频；错误记录保存在 `sakura/cpu-fp16-threads8/`，没有绕过准入或把失败计入耗时。

工作集和私有内存覆盖该进程的加载、请求与卸载，每 100 ms 采样自有进程树，可能遗漏短暂峰值或重复计算共享页。Genie 行取前后两轮各自峰值中的最大值，Sakura 各配置为一轮进程峰值，不是请求内存的中位数。512 容量只跑短句，不能作为长句内存与其他行比较。AMD 的进程工作集不等于完整 GPU 分配，也不能直接与 WDDM 数值相加；前次独立 GPU 资源探针见[精度实验](cpu-amd-precision-listening-20260927.md)。

Genie 保留参考编码所用的 HuBERT / SV 等资源，Sakura 使用事先离线准备的参考。因此内存差异包含模型组织、参考预处理、会话和线程设置，不能全部归因于 INT8 或 FP16。没有测量整机功耗、后台应用响应或多请求并发。

每次 Genie 请求的随机状态都会推进，音频长度随之变化；Sakura 每次请求重置固定 seed。测试没有随机轮换配置，也没有锁定温度、功耗和桌面后台负载。前后两轮只能帮助识别明显漂移，不能替代更多音色和语料上的统计检验。

## 结果解释

CPU INT8 配置的长句完整请求耗时比本轮 Genie 中位数少 25.3%，采样峰值工作集少 78.3%。这是当前输入和产品路径的实测差异，音质、语速和信息完整度仍需试听确认。

AMD FP16 1280 配置的长句完整请求耗时比本轮 Genie 中位数少 43.1%，采样峰值工作集少 65.5%。这是当前输入和产品路径的实测差异，音质、语速和信息完整度仍需试听确认。

当前可用的 CPU FP16 配置在这台处理器上没有速度优势；前次内核检查发现它没有 AVX512FP16，主要声学运算仍由 FP32 内核完成。CPU FP16 图更小并不代表执行更快；同为 2 线程的早期 FP32 / FP16 对照见[独立精度实验](cpu-amd-precision-listening-20260927.md)。AMD 512 容量面向短句，本轮长文本的 Prefill 已超过容量，会明确报错，不能当作通用长句配置。

## 初始化、首包和 CPU 时间

每次请求均只返回一个 PCM 块，首包时间近似完整请求时间，不能据此宣称流式播放更早开始。`ready_ms` 与冷请求时间分开保存：两种实现的延迟加载位置不同，单独比较 `model_load_ms` 会误导。归档中的 worker 入口至首 PCM 近似值不含 Python 进程启动与脚本顶层导入，也包含资源哈希、包枚举开销，不作为完整冷启动性能结论。

| 配置 | worker 入口至首 PCM 近似值 s | 长句主进程 CPU 时间中位数 CPU-s |
|---|---:|---:|
| Genie 原版 CPU（前测） | 13.129 | 70.531 |
| Genie 原版 CPU（后测） | 11.441 | 69.188 |
| CPU FP32，8 线程 | 6.002 | 20.125 |
| CPU FP16，2 线程 | 10.142 | 35.688 |
| CPU INT8 GPT + FP32 声学，8 线程 | 5.093 | 17.047 |
| AMD FP16，容量 1280 | 6.825 | 7.641 |
| AMD FP16，容量 512，仅短句 | 6.322 | — |

CPU-s 是线程累计占用的处理器时间，可能超过墙钟耗时；此列不含前端子进程，归档另保留采样进程树 CPU 时间。它不是整机 CPU 百分比或功耗。

## 试听与完整性

未处理 WAV 在 `outputs/genie-comparison-20260927/试听说明.md`。各配置固定选择首个热请求，没有按速度或听感筛选。复制文件与原始 WAV 哈希一致，均为 32 kHz 单声道 PCM16；没有调音量、拼接、裁剪或变速。人工听音和 ASR 尚未验收。

有效配置共完成 59 次完整请求，所有观测到的自有进程自然退出，无超时或强制结束。另有上述 8 线程 CPU FP16 配置拒绝记录。12 份原资源与 58 份 Genie Python 源文件哈希复核未变。
