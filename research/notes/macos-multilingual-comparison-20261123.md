# SakuraTTS 与 GPT-SoVITS 的 Mac 多语种对照

测试时间为 2026-11-23，设备为 Apple M4（10 核 GPU）、16 GiB 统一内存，macOS 26.5.2（25F84）。SakuraTTS 取 `20a8abd6b769b9318dad1509ddb219456ad05013` 的源码，使用 MLX 0.32.2。GPT-SoVITS 取项目固定的 `48b1a0169a28582a8984402f82cf438d3bfa6aca`，使用 PyTorch 2.7.1，设置 `device: mps`、`is_half: false`，未开启 MPS CPU fallback。两者按顺序运行本地 HTTP 服务，复用同一对官方 V2ProPlus 权重和参考音频。两套环境的日语处理均使用 pyopenjtalk-plus 0.4.1.post9。SakuraTTS 的 GPT prefill 为 CPU FP64，语义解码及声学后段为 Metal FP32，中文特征在 CPU 上计算。

原版复用本机 Python 3.11.15 准备环境，使用 NumPy 2.4.6、librosa 0.11.0。原版 requirements 中这两项分别为 NumPy <2 和 librosa 0.10.2。

主要对照使用单项批次、`cut5`、关闭分桶和并行、`top_k=15`、`top_p=1`、`temperature=1`、重复惩罚 1.35，语速 1。热请求使用 1234、1235、1236 三个固定种子。首条请求和流式请求使用 1234。两套引擎的采样实现不同。RTF 为完整请求时间除以生成音频时长。RSS 以 50 ms 间隔采样进程及其子进程，共享页可能重复计算，瞬时峰值也可能漏采。

热请求里，SakuraTTS 在六项日常单语及混读用例的 RTF 低约 27%–42%。首条新参考及首条普通话仍明显慢于原版 MPS，普通话热请求的进程树峰值 RSS 也更高。两套服务的中英和三语混读样例均生成 WAV，自动转写仍有较大偏差。

## 磁盘与交付范围

同一对原始权重约 0.33 GiB。SakuraTTS 三语模型缓存约 2.40 GiB，其中离线中文资源约 1.71 GiB。原版的 BERT 和 G2PW 源资源约 1.20 GiB。这里统计模型与语言资源文件，未把共享解释器、准备环境和测试下载计入发行包大小。

本次从源码测试。Mac 整合包 recipe 声明日英，中文由本次准备的资源和依赖提供。普通话和混读结果可用于决定 Mac 中日英包的后续验收。本次未重打包、未做独立干净解压验收或正式人工盲听。
