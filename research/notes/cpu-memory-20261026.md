# CPU 推理内存测量（2026-10-26）

本次保留 CPU 默认的 `int8` / `resident` 策略，关闭 GPT 随输入形状增长的 ORT memory pattern 缓存，并增加 `low-memory`、`minimum-memory`、`compact` 三个显式预设。前两个复用已有的 KV 释放和模型错峰生命周期；`compact` 将已有有限感受野声码器分块扩展到 CPU FP32，另提供 128 帧和两层错峰的组合。它们不改变精度、容量、采样、文本切分和停止规则。用法见 [CPU 指南](../../docs/cpu-amd.md#cpu-省内存档位)。

## 复现条件

- 基线为提交 `88395f9e535ddbbd9a3914f6d16f3a20868e561c` 对应的 CPU 实现。2026-10-15 部署归档中的 118 个 Python 源文件与修改前工作区逐文件 SHA256 一致。
- Sakura V2ProPlus，INT8 GPT、FP32 声学，中性参考，日文，seed 1234，`cut0`，GPT / 声学各 2 线程，容量 2048。本机配置载入五个已有参考，ECS 载入一个中性参考；两端使用的中性数组相同，各端前后配置固定。采样参数和完整文本保存在各轮 `result.json`。
- GPT 图 SHA256 为 `4b9c6d3ad45ce9f29114937b9169bd0917074e7d24f1fd7962534d37384b07d0`，声学权重为 `62ddd22044bc1d6efeaf474aa2e9bb8b65d525d6e970ead3c7a3f9850d150fdd`。两台机器复用相同模型、参考数组和前端资源。
- 本机为 Windows、Ryzen 7 9700X，复用整合包 Python 3.11.15、NumPy 2.4.6、ORT 1.30.0。测试所需模块从本地运行包和缓存复用。ECS 使用已有 Python 3.12.3、NumPy 2.4.6、ORT 1.30.0 环境。
- 每轮新建进程，`Engine.load`、显式加载 GPT / 声学、首次短句分别计量。首次请求前不运行模型预热，也不清空 OS 文件缓存。与旧 ECS 脚本相比，模型懒加载移出首句单独计量，并取消只用于测首片时间的回调。加载次序和背景状态会影响分配器与 RSS；旧报告约 1.53 GiB 与本轮基线的差距不能记为代码收益。各候选只与本轮同脚本基线比较。
- 内存轮在本机每 50 ms、ECS 每 100 ms 采样。正式计时轮不启动采样线程、不安装阶段钩子，排除 WAV 写盘。每轮首次短句 1 次，正式计时另有热短句 3 次、长句 2 次；本机内存轮采用相同次数，ECS 内存轮采用热短句、长句各 1 次。空闲点取音频保存、释放后 2 秒。

入口为 [cpu_memory.py](../tools/cpu_memory.py)。例如：

```sh
python research/tools/cpu_memory.py --model MODEL --output outputs/cpu-memory-run \
  --mode memory --profile low-memory
python research/tools/cpu_memory.py --model MODEL --output outputs/cpu-timing-run \
  --mode timing --profile low-memory
```

原始产物位于 `outputs/cpu-memory-20261026/`：源文件快照、输入哈希、采样、PCM、逐次报告、测试日志和 ECS 启动脚本。`exclusions.txt` 标明调试失败及早期重叠运行；这些记录不进入正式计时。正式各轮串行运行。汇总和逐份 WAV 比较保存在 `all-summary.json`、`all-pcm-comparisons.json`；`summarize_all.py` 可从原始结果重建。

## 占用来源

GPT 的 Prefill / Decode 原本就共用一个 ORT Session，没有重复加载原始 FP32 Transformer 权重。INT8 图常量约 73.64 MiB，NumPy embedding 约 13.25 MiB；声学图常量约 237.05 MiB。关闭预打包的试验没有明显降低 RSS，完整长句反而变慢，未采用。

KV 两个数组合计分配约 192.1 MiB，保留全部 2048 容量。容量字节数不等于 RSS：未写入的页可能尚未常驻。本机长句后释放 KV，RSS 实降约 98 MiB。`low-memory` 在声学开始前释放这部分请求状态，下一片重新 Prefill，不复用旧请求语义。

本机基线的阶段边界 RSS：引擎初始化后约 81 MiB，GPT 加载后约 183 MiB，声学 Session 加载后约 226 MiB；首次文本处理后约 359 MiB，首次语义生成后约 398 MiB，首次声学结束后约 606 MiB。映射权重会在首次计算时按需进入 RSS，不能把加载边界差值当作全部模型内存。语言识别模型、OpenJTalk / Sudachi 字典也是常驻来源，不绕过原语言规则来省内存。

长句声学阶段是本机观测峰值所在。ORT 逐节点统计显示 `/dec/ups.2/ConvTranspose` 单次临时分配约 257.34 MiB，其他上采样临时分配约 32–129 MiB；部分声码器节点的动态输出约 64.34 MiB。这些分配的寿命不同，不能将各节点数字相加作为峰值。最终长句 FP32 波形只有约 2.68 MiB，PCM 约 1.36 MiB，输出数组复制不是主要峰值来源。原始统计见 `acoustic-diagnostic/nodes.csv`。

GPT Decode 的历史长度每步变化，ORT 会按输入形状保留分配计划。关闭这一缓存仍由原有连续 KV 数组保存历史，不增加缓存、重载或强制 GC。上游实现见 [ORT 1.30.0 SessionState](https://github.com/microsoft/onnxruntime/blob/v1.30.0/onnxruntime/core/framework/session_state.cc#L868-L951)。本轮 resident 的收益较小，不能将整个模型工作集视为可回收缓存。

## 本机结果

RSS 使用二进制 MiB。内存取独立资源轮的操作系统 RSS 高水位，耗时取不采样的完整请求。两轮旧版基线给出各轮中位数范围，候选各一轮；样本不足以给出稳定 p95。

| 路径 | RSS 高水位 | 最后长句后空闲 RSS | 热短句中位数 | 长句中位数 |
| --- | ---: | ---: | ---: | ---: |
| 修改前 resident | 1140.6 MiB | 752.0 MiB | 1.52–1.66 s | 9.65–9.67 s |
| 修改后 `int8` / resident | 1133.2 MiB | 746.3 MiB | 1.55 s | 9.70 s |
| `low-memory` | 1034.6 MiB | 647.7 MiB | 1.49 s | 9.52 s |
| `minimum-memory` | 936.4 MiB | 294.9 MiB | 2.94 s | 10.86 s |
| `compact`（256 帧，模型常驻） | 748.2 MiB | 640.9 MiB | 1.65 s | 9.98 s |
| `compact` + 128 帧、两层错峰 | 488.6 MiB | 294.2 MiB | 2.80 s | 11.63 s |

`low-memory` 本机未见明显减速；`compact` 的长句约慢 3%，峰值约降 34%；两层错峰约降 57%，短句加载成本明显，所以都不替换默认策略。本机短句 PCM 为 4.14 秒，长句为 22.26 秒。13 轮共 78 份 WAV 均完成 PCM 比较，候选与基线逐采样一致，停止原因和语义 token 一致。不能将本机 INT8 数值、音频长度和速度直接套用到 ECS。

模型加载与首次请求分开记录：不采样的常驻组合模型加载为 1.21–1.75 秒，首次短句为 1.74–2.05 秒；总体错峰不提前加载模型，首次短句 2.94–3.01 秒，已经包含加载。初始化文本资源另计约 0.26–0.37 秒。原始每阶段时间保存在汇总中。

## ECS 内存与占用来源

ECS 复用 `aliecs` 上的旧环境与模型。测试目录为 `/opt/sakuratts-cpu-memory-20261026`，旧目录 `/opt/sakuratts-bench-20261015` 保留。源码对照再次确认本机基线与 ECS 基线的 118 个 Python 文件一致。

每轮独立 transient systemd service，沿用 `MemoryMax=2200M`、`MemorySwapMax=512M`、`CPUQuota=150%`、`Nice=10`，另设 1200 秒运行上限。没有修改常驻服务配置。资源限制见 `run_ecs*.sh` 和运行中保存的 `*-active-unit.txt`。服务退出后 systemd 可能回收瞬态配置，不能把此时 `systemctl show` 的默认值当作执行时配置；同样不采用退出汇总中偶发的几百 KiB “Memory peak”。cgroup 峰值取进程退出前读取的内核文件。

| 路径 | VmHWM | 100 ms 采样峰值 | 长句后空闲 RSS | cgroup memory.peak |
| --- | ---: | ---: | ---: | ---: |
| 修改前 resident | 1348.0 MiB | 1347.7 MiB | 876.0 MiB | 1668.4 MiB |
| 修改后 `int8` / resident | 1345.7 MiB | 1345.6 MiB | 878.2 MiB | 1217.1 MiB |
| `low-memory` | 1234.9 MiB | 1189.7 MiB | 710.8 MiB | 1239.0 MiB |
| `minimum-memory` | 1095.3 MiB | 1092.8 MiB | 422.2 MiB | 861.4 MiB |
| `compact` | 1243.8 MiB | 1171.6 MiB | 721.1 MiB | 1151.6 MiB |
| `compact` + 128 帧、两层错峰 | 684.1 MiB | 660.2 MiB | 444.8 MiB | 722.2 MiB |

RSS 和 cgroup 是独立口径，不能相加或相减。RSS 包括进程映射的常驻文件页；共享文件页的 cgroup 记账可能归属于此前访问它的 cgroup。第一轮与后续轮的文件缓存记账归属不同，`int8` 的 cgroup 峰值下降不能解释为优化释放了约 451 MiB；它的 RSS 没有可确认的实质改善。分块包另有独立权重文件，同样会改变文件缓存记账。内存轮只有一次长句，计时轮重复长句的 VmHWM 另见原始汇总，不能把此表当作任意请求序列的上限。

分阶段采样解释了本机与服务器的差别。原版 ECS 的 GPT 峰值约 1084 MiB，声学峰值约 1348 MiB；`compact` 声学阶段降到约 838 MiB，但 GPT 阶段达到约 1172 MiB，成为整体峰值。仅继续缩小声码器块，无法消除语义阶段同时驻留两类模型、KV 与临时张量的成本。两层错峰的 GPT / 声学采样峰值分别约 660 / 598 MiB，代价是逐片重建模型。

每轮结束后的独立分配器诊断显示，普通 resident 下 `gc.collect()` 没有降低 RSS，`malloc_trim(0)` 约回收 64 MiB。它只用于判断 glibc 保留的可归还页，不计入上表空闲收益，不加入产品路径。KV 释放、模型卸载后仍有前端、字典、库及分配器保留；空闲 RSS 不会归零。

本轮内存样本的进程 `VmSwap` 和 cgroup `memory.swap.peak` 均为 0，cgroup `memory.events` 的 max / oom / oom_kill 均为 0。整机 `MemAvailable`、swap 已用量及累计换入换出是另一组指标；它们包含机器人、QQ、数据库等所有业务，不能记入 TTS 自身换页。各轮开始时系统状态不同，也没有清空文件缓存，不能把跨轮可用内存的增长全部归因于代码优化。

| 路径 | MemAvailable 开始 / 最低 / 空闲 | 系统 swap 已用开始 → 空闲 | 累计换入 / 换出增量 |

## ECS 延迟与输出

正式计时不启动资源采样线程。表中范围为不同轮的中位数范围，并非置信区间；每轮热短句 3 次、长句 2 次。旧版基线 3 轮，`low-memory` 和两层错峰各 2 轮，其余各 1 轮。后台业务继续运行，单轮之间存在明显波动，不能将最快一轮当作稳定加速。

| 路径 | 模型加载 | 首次短句 | 热短句中位数 | 长句中位数 |
| --- | ---: | ---: | ---: | ---: |
| 修改前 resident | 1.70–1.99 s | 6.47–7.02 s | 5.56–6.05 s | 35.06–40.10 s |
| 修改后 `int8` / resident | 1.88 s | 5.77 s | 5.15 s | 37.37 s |
| `low-memory` | 1.81–1.85 s | 6.39–6.93 s | 5.82–5.89 s | 38.31–42.32 s |
| `minimum-memory` | 片段内加载 | 8.89 s | 7.32 s | 40.88 s |
| `compact` | 1.35 s | 6.54 s | 6.57 s | 35.81 s |
| `compact` + 128 帧、两层错峰 | 片段内加载 | 8.14 s | 7.09–7.17 s | 38.65–42.96 s |

`low-memory` 的短句接近基线，长句两轮的中位数分别为 42.32、38.31 秒，未显示稳定加速，也不足以排除较小的延迟代价。两层错峰的短句增加约 1–2 秒，长句仍受后台负载波动影响。默认 resident 继续保留；内存优先时显式选择档位。

六次请求的计时轮也在计时边界外读取 VmHWM：基线为 1359.6–1411.1 MiB，`low-memory` 为 1241.5–1300.9 MiB，`compact` 为 1265.7 MiB，两层错峰为 684.5–723.9 MiB。重复请求和分配器保留使高水位不同于三次请求的独立内存轮，两组数据均保留。两层错峰减少约一半进程峰值，但不代表任意长文本都能保持这个上限。

ECS 共 16 轮、78 份 WAV：70 份与本轮基线 PCM 完全一致；其余 8 份均为分块长句，每份在 688000 个 PCM 样本中有 13 个相差 1 LSB，其余样本一致。所有轮的音频长度、语义序列、停止原因一致：短句 4.14 秒，长句 21.50 秒。旧版与保持整图的所有候选 PCM 一致，本轮基线也与升级前保存的输出 PCM 一致。分块差异属于本次单独记录的数值变化，没有作为 PCM 完全不变的优化宣称通过。

所有临时服务均以 success / 0 退出，最终没有残留测试服务或 `cpu_memory.py` 进程。前后检查的 `sakura-console.service`、`sakura-telemetry.service` 保持 active，PID 分别为 874、875；没有停止其他业务或修改常驻配置。完整服务寿命还包括初始化、空闲采样和解释器退出等待，单个服务完成请求后曾继续等待约两分钟才退出；该等待也出现在保持整图的路径，本轮没有定位其根因，请求计时不包含它。相关状态和日志保存在 `ecs/`。

尚未减少的主要成本包括 GPT 阶段的完整上下文计算与临时张量、常驻语言资源及分配器保留。声码器分块不能消除这些占用；进一步压低 resident 峰值需要专门检查 GPT 的分配与执行图。本轮没有找到可以直接替换默认路径、同时大幅降低峰值且不增加等待的方案。

## 未采用的试验

| 试验 | 本机结果 | 处理 |
| --- | --- | --- |
| 关闭声学内存复用 | 峰值约 1137 MiB，收益不明显 | 保持原设置 |
| 关闭 ORT 权重预打包 | 峰值约 1136 MiB；采样轮长句约 11.24 s | 保持预打包 |
| 开启 CPU arena 并逐次收缩 | 峰值约 1553 MiB，反而增加 | 不加入产品路径 |
| FP32 多相卷积替换 ConvTranspose | 完整请求峰值约 1139 MiB，没有改善 | 不修改默认声学图 |
| 现有 FP16 声学图直接运行 CPU | 声学独立回放：长句 10.28 s，FP32 为 5.61 s；RSS 高水位 819.6 / 707.1 MiB | 不加入 CPU 预设 |

多相卷积用同一份语义、参考和噪声独立回放。长句波形最大绝对误差 `2.03e-6`、RMSE `5.87e-8`，通过事先固定的 FP32 `atol=1e-4, rtol=1e-5` 检查，但长句有 505 个 PCM 样本相差 1 LSB，短句有 72 个。该候选仅保留本机实验，未作为 PCM 不变的优化发布，也未上传 ECS。

FP16 候选的声学回放结束后 RSS 比 FP32 低约 102 MiB，但长句耗时增加约 83%，峰值也更高。长句波形 SNR 约 44.45 dB，PCM 最大差 650 LSB，未做听音；并非降低精度就能同时节省 CPU 内存和时间。该结果只覆盖本机已存在的 `fp16-candidate-basic` 图，没有在 ECS 上测试 FP16。

## 验证范围

109 项相关测试通过，覆盖小型真实 ONNX GPT 的 Prefill / Decode、容量与失败释放，CPU 档位的 PCM、Session 生命周期与显式覆盖，精度错配，采样停止、取消恢复、managed 错峰，共享 DirectML / CUDA 声学边界，以及转换缓存和发布。新增真实 CPU ONNX 测试覆盖分块首尾、完整长度、重复请求、resident / staged 两种声学生命周期；有限感受野测试覆盖 Sakura 全部 640 个上采样相位。日志为 `tests-final-runtime.log`（83）、`tests-final-public-r2.log`（9）和 `tests-conversion.log`（17）。

本机从原 FP32 ONNX 包实际生成独立分块包，完成公共 Engine 推理及 `doctor --backend cpu --profile compact` 检查；后者只确认资源和依赖，不当作推理验收。便携解释器的子进程测试会读到包内旧模块，相关测试改用已有系统解释器。首次诊断缺少本地复用模块的发行元数据，补齐同版本本地元数据后通过，没有修改产品来绕过环境限制。失败记录保留。

本轮复用了已准备模型与参考，不包括原始检查点的完整首次导出、陌生参考编码、HTTP 并发、GPU 真机回归或整机独占性能。未进行人工听音和 ASR；PCM 或 1 LSB 误差只说明这组输入的前后差异，不扩大已有模型质量验收范围。未改动常驻业务的配置或模型。
