# N.A.V.I. 情绪表情

独立的 MaiBot 回复扩展插件。Planner 在组织回复时判断要不要配表情，以及哪种神情符合当前话题和准备说的话；选定后与正文一起交给回复流程。只发送 `assets/` 中的三张原图，不接受文件路径、网址或其他图片参数。

将本目录复制到 MaiBot 的 `plugins/navi_expressions/`，在 WebUI 加载插件。也可以使用 WebUI 的 ZIP 安装入口。版本要求见 [_manifest.json](_manifest.json)。插件没有额外 Python 依赖，也不调用图片模型或定时发送。

日常配表情使用 `reply.plugin_options["rvosy.navi-expressions.expression"]`，包含必填的 `emotion` 和可选的 `mode`。没有合适的表情就省略此扩展，照常回复。三种表情的语义在扩展描述中直接提供，调用前就要选定，人物卡无需增加工具格式。Replyer 会收到选定神情的说明，正文应独立成立，不预告附件。固定插画背景与现实位置也会在回复上下文中区分。

表情追加在同一次回复的正文之后；与 SakuraTTS 同时启用时，顺序为正文、语音、表情。扩展只组装消息，由 Host 统一发送，不会在生成正文之前抢先发表情。前面的消息发送失败时，Host 停止后续发送；没有对白时不追加表情。概率未命中时保留原回复。

| 用户要求单独展示时的工具 | 原图名称 | 神情适用语境 |
| --- | --- | --- |
| `navi_expression_happy` | 开心 | 被夸奖后开心地感谢、满足或温柔回应；“笑一个”“看看你的笑脸” |
| `navi_expression_serious` | 无奈认真 | 带着无奈纠正误解、认真提醒或解释 |
| `navi_expression_unexpected` | 意料之外 | 没想到的话题转折、突然被调侃而意外 |

三个独立工具仅用于用户明确要求单独展示，模式为 `requested`；它们不再接受自主发送。日常自主表情由回复扩展的 `mode=auto` 处理。概率由距本会话上次成功发送任意一张表情的时间决定：最短间隔内为零，之后按经过时间与恢复时长的比例线性增加，上限为配置的最高概率。首次发送按最高概率计算。参数和默认值由 [plugin.py](plugin.py) 的 `ExpressionConfig` 定义，计算逻辑为 `auto_probability`。

概率只在模型选定随回复的表情、准备发送时计算，不是按每条群消息计算。未抽中不会重置上次发送时间。三种表情共享本会话的发送时间和抽取间隔，换表情不能立即重抽。未抽中和间隔内都静默跳过。发送回执 Hook 只在这三张素材实际发送成功后更新发送时间；组装附件不算成功。

`mode=requested` 用于用户本轮主动要求看表情或角色样貌，直接跳过概率和间隔。模式由 Planner 根据上下文选择，工具描述区分了“笑一个”与普通夸奖，自主发送不得冒用 requested。用户请求发送成功后也更新上次发送时间，但不妨碍下一次用户主动请求。调用异常保留已预约的抽取间隔，且不伪造成功时间；没有自动重试或补发。

发送时间与抽取间隔保存在 SDK 分配的插件数据目录 `send_state.json`，重启后继续生效。发送使用单张 `emoji` 消息，并将表情名称同步到当前会话历史。SnowLuma 适配器将它编码为 QQ 表情包（`sub_type=1`）；原 PNG 的内容和尺寸不变。

如果安装了旧版 `emoji_send_policy`，需同步更新为 [固定表情发送策略](../maibot_emoji_send_policy/README.md) 1.1.0。旧版会拦截所有表情包；新版按图片实际字节校验，只放行这三张素材，通用表情库继续禁用。插件本身不限制其他工具的普通图片用途。

`assets/` 为用户提供的 N.A.V.I. 图片，按原样保留；插件源码的 MIT 许可证不覆盖图片权利。附件原文件名与调用名的对应关系见 [素材说明](assets/README.md)。

验证命令（安装对应版本的 `maibot_sdk` 后）：

```shell
python -m unittest discover -s integrations/maibot_navi_expressions/tests -v
```
